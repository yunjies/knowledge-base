# 规范文档的「LLM 第一读者」可读性审核报告

本文记录的是 workbench 技能文档的一次审核，作为审计样本保留。报告中的测试计数、`tests/global` 路径和未修复项仅描述该次 workbench 审核，不代表 knowledge-base 当前状态。审阅 knowledge-base 时，应从当前技能文件与 KB 守护现场取证。

**审核对象**：`.agents/skills/` 下四组 skill（`rule-card-writing`、`spec-book-writing`、`doc-writing`、`process-doc-writing` 各自的 `SKILL.md` 与 `reference/*constraints.md`）。**读者前提**：本批文档的第一读者是 **LLM**，且是**要照着它动手的 agent**。**判定原则**：判据不是「人读起来顺不顺」，而是**一个零历史、只读该文档的 LLM 能否把任务做对、并在做完后自我验证**。

## 一、视角集合（从 LLM 读者特性推出）

LLM 读者的四个不可回避的特性各自对应一个关注面，两两不重叠：

| 视角 | LLM 特性 | 失效形态 |
|---|---|---|
| L1 上下文载荷与定位成本 | 上下文有限、只能线性读入、跨文件需重取 | 读入远超必要量、需维持跨位置状态 |
| L2 可解析性与结构化程度 | 靠模式补全而非形式化解析 | 对未定义名与不相称结构做静默补全 |
| L3 任务可执行性 | 读完要动手，需停止条件 | 无法确定产出物，或无法自验对错 |

**第二轮（范围扩到全部四组 SKILL）新增四个视角**，针对"多份文档同时持有"这一 LLM 真实处境：

| 视角 | 关注面 |
|---|---|
| M1 入口自足性 | 只拿到 SKILL.md（唯一常驻注入）能否开工、能否定位 reference |
| M2 完成信号 | 有无不依赖自我感觉的"我做对了"判据 |
| M3 跨文档口径一致性 | 被两份以上文档分别陈述的同一事实是否等价 |
| M4 解析歧义与未定义名 | 未定义名、同名异义、前向引用导致的静默补全 |

## 三、验证证据

- `node scripts/verify.js` → exit 0（三类登记与 §0.5 双向完备、互斥、锚点全通、SKILL.md 路由表一致）
- `node --test` → **21/21 通过**（较基线 +12 用例）
- 破坏复验（均在临时副本上）：路由表错指 `artifact→F-07` → exit 1；SKILL.md 跨文件锚点写错 → exit 1；删掉路由表 → exit 1
- 全库锚点复算：全部带锚点链接可解析（含新增的四份路由表）
- `agents-doc-hygiene` → **19/19 通过**（新增两条门禁，见下）
- `npm test` 的通过与失败数与 HEAD 基线完全相同（失败项全在 `host/`，非本轮引入）

**新增工程门禁**（`tests/global/agents-doc-hygiene.test.js`）——把本轮的两类缺陷变成机器守护：

1. `every skill cross-file anchor resolves to a real heading`：遍历 `.agents/skills/**/*.md` 的全部带锚点链接，逐个解析到目标文件的实际标题；不存在的文件或锚点即失败。这使"路由表指向一个不存在的章节"这类比没有路由表更坏的错误无法再进入仓库。
2. `every skill entry point carries a routing table`：每份 `SKILL.md` 必须含 `## 路由表`。reference 短且自索引者可写一行指向它，但不能没有——因为 `SKILL.md` 是唯一常驻注入的文本。

两条门禁都在加入时**当场抓到了真实缺陷**（前者抓到我写错的一处相对路径，后者抓到 `spec-book-writing` 缺路由表），已一并修复。

## 四、结论

四份文档在**内容正确性**层是健康的（登记纪律、锚点可达、判据源编号零断链）；缺陷集中在**作为 LLM 作业入口**这一层：入口的绿灯曾指向错误对象、长文档缺定位入口、未定义名与同名异义诱发静默补全。

第二轮把范围扩到全部四组后，最严重的发现是**两处真值相反的跨文档口径**（卡片字段行的并列项承载形态、SKILL 自述的判定面），它们都发生在"LLM 同时持有数份文档"的交界处——单看任何一份都自洽，只有并置才暴露。这印证了 M3 这一视角的必要性：LLM 不会察觉两处口径冲突，只会随机采用一处。

最高杠杆的一处改动是 **路由表**：单点同时缓解 L1 的定位成本、行距回跳与中段衰减三项。它必须落在 `SKILL.md`——路由表要在**取回规范之前**起作用，放在规范内部等于要求读者先打开全文才能知道该读哪里。现已由门禁强制四份都具备。
