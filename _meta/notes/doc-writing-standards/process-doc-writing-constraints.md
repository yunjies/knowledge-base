# 流程类文档撰写规范

本册约束流程类文档的结构——即以流程图及其配套说明承载内容的文档，涵盖 H1 标题、正文组织与图本身。本册按条目组织；未枚举情形由各条目主句内嵌的判据裁决。

## F01 · H1 之后以自然段陈述本图的核心目标

**流程类文档在 H1 标题之后，首个内容块是陈述本图核心目标的自然段落**——不得直接起图、起列表或起背景铺垫。判据有两条：只读 H1 与该段，读者能否判断这张图是否回应自己面对的问题；若把目标移入图内节点或留到图后，读者是否被迫读完整个图才知道它要说明什么。

**边界与例外**

- **标题已完整给出目标**：该段转为陈述本图的范围与产出（从哪开始、到哪结束），不复述标题。
- **一册多图**：每张流程图各自有陈述其目标的段落，前一张的目标段不替代后一张。
- **只管首块**：本条不规定该段与图、图例的先后，只规定 H1 之后的首个内容块不是别的。

## F02 · 首个 h2 只承载主流程图

**流程类文档的第一个 h2 章节只承载主流程图**——该章节的正文只有流程图本身，且主流程图只画主干，子流程图不得内联其中。判据有两条：只读该章节，读者能否得到一张不被子流程细节干扰、可独立读懂的主流程图；图内每个节点，其内部步骤是否无须另起一张图即可讲清——出现"须另起一图方能讲清"的节点，该内容即属子流程，留在本图内即违规。

**边界与例外**

- **入口节点留在本图**：与子流程对应的位置保留其入口节点，主流程图的连线经过它；被移出本图的是子流程的内部步骤，不是它在流程中的位置。
- **子流程蓝图节点承载自身的图**：子流程图不占与主图并列的独立章节，而是画在触发它的那个子流程蓝图型节点的章节内（见 F08）；主流程图章节不复述子流程的内部步骤。
- **只含图**：本节除流程图本身外不出现其他内容块。
- **单图文档**：文档只含一张流程图时，本节即全图，不因缺少后续子流程章节而违规。

## F03 · 节点分标识符与描述名两槽，描述名同图内不得重名

**mermaid 中每个节点的标识符用标准化英文书写，面向读者的描述名另置一槽**，书写形态为 `ID["描述名"]`；同一张图内描述名不得重名。判据有两条：**标识符自足**——脱离该图的其余部分、只看标识符，agent 能否大致判断该节点在流程中的作用（`CHECK_TOKEN` 通过，`N3`、`A1` 不通过）；**描述名唯一**——在同一图内检索该描述名，能否只命中一个节点。

**边界与例外**

- **描述名用自然语言**：它以人为读者，可用中文与任意自然语言，不受标识符的英文约束。
- **标识符不进渲染面**：标识符只承担图内引用与机器阅读，不当作描述名使用；描述名也不承担引用职责。
- **跨图重名放行**：唯一性以单张图为范围——两张图各自有 `START` 或同名描述名，不违规。
- **标识符随引用一同更名**：标识符是全图引用的锚点，改名须连同连线与 `subgraph` 引用一并改，不得留下指向旧名的边。

## F04 · 节点按角色分型，同型取固定形状

**每个节点按其在本图中的角色归类，同一角色的节点取同一形状**，形状与角色的对应关系在本册内固定，不随图而异。角色与形状的对应为：开始与结束型取圆角括号 `(["..."])`，条件型取花括号 `{"..."}`，功能逻辑型取方括号 `["..."]`，子流程蓝图型取双方括号 `[["..."]]`。

**边界与例外**

- **角色由图中的功能决定，不由文本内容决定**：节点写"判断"二字不使它成为条件型；决定它的是它在流程中分叉与否。
- **新增角色须同时定形状**：引入本册未列的角色时，为该角色指定形状并登记进本册，不得就地选一个顺手形状。
- **只用 mermaid 原生形状**：不自造形状、不改渲染器；形状的可取集合以渲染管线实际支持的为准。
- **装饰不承担角色**：颜色与样式用于强调，不得充当角色区分——形状才是角色的承载，因为形状在无色渲染下依然可辨。

## F05 · 允许成环，但每个节点都须可达完成节点

**流程图允许成环**（重试、轮询、回退这类真实回边），**但图中每个节点都须存在沿有向边到达某个结束型节点（完成节点）的路径**——节点若只能回到环内、无法流向完成节点，该图即违规。判据：对图中每个节点做一次沿出边的可达性遍历，是否都能命中至少一个结束型节点；命中不了的节点即违规点。环的存在不豁免该判据——环必须带一个通向完成节点的出口。

**边界与例外**

- **成环不是缺陷**：被判违规的是"无出口的环"，不是环本身；循环等待、轮询、失败重试写法合法。
- **无出边的非结束型节点同违规**：它与无出口的环同属死胡同，由同一判据抓出。
- **范围限于单张图**：本条约束单张图内的可达性；主流程图与各子流程图之间的连接由 F02 的入口节点承担。
- **不要求反向可达**：本条只要求"每个节点能流向完成节点"，不要求"完成节点之前的每一步都能从开始节点到达"——后者是另一条判据，本册未立。
- **结束型节点的角色名与形状见 F04**：本条只规定可达性，不重复其形状定义。

## F06 · 主流程图之后逐节点成章，以自然语言详述其逻辑

**主流程图章节之后，主流程图的每个节点各占一个章节**，章节以自然语言描述该节点的逻辑内容。判据有两条：**覆盖**——主流程图里的每个节点标识符，能否在本章之后找到恰好一个以其为标题的章节（一一对应，不重不漏）；**自足**——只读该章节，读者能否说出该节点做什么、以及它在什么条件下走哪条出边，无须回看主图。

**边界与例外**

- **章节标题取节点标识符**：标识符是节点与章节之间的对应锚点（命名见 F03）；节点改名时，其章节标题随之更名。
- **章节为 h2**：主流程图章节只含图（见 F02），节点详述无法内嵌其中，故与它并列。
- **每个节点至多一个章节**：同一节点的详述不得分散在两处。
- **用自然语言，不粘贴图片段**：本章承载图之外的信息，复述图的语法不增加可核实的事实。
- **子流程图的节点同等适用**：子流程图章节之后同样逐节点成章；子流程图自身的章节与其节点章节的次序，照本位次递归。
- **成环节点同等适用**：环内节点各成一章，不因 F05 允许成环而豁免。
- **子流程蓝图型节点按其自身条目展开**：它承载一张子流程图，展开形态见 F08，不适用本条的"以自然语言详述逻辑"。

## F07 · 输入参数与输出参数按固定槽位标准化描述

**每个节点详述章节须以标准化形态列出该节点的输入参数与输出参数**，两者齐备；参数按其来源与去向分槽书写，形态为 `` - `参数名`：类型描述；来源为 X `` 与 `` - `参数名`：类型描述；去向为 X ``，其中 X 取上游或下游节点的标识符，参数来自流程之外时取该外部来源的名目（如工程部署位置）。判据有两条：**齐备**——章节内能否同时找到输入与输出两栏，且两栏都不省略；**同名同义**——同一参数在全文档内只有一个名字，上游节点的输出与下游节点的输入对得上。

**边界与例外**

- **无参数不是无栏**：节点无输入或无输出时，该栏显式写"无"，不得整栏省略——省略与"无"在读者处不可分辨。
- **参数名与节点标识符同一命名域**：参数名用标准化英文（见 F03），不与之重名。
- **类型描述是自由文本**：本册不规定类型的取值集合，按该参数的实际语义写（如路径、布尔、枚举及其取值、状态描述）；同一参数在多处的类型描述须一致。
- **范围限于节点详述章节**：本条约束详述章节内的参数描述，不约束图内节点的描述名。

## F08 · 子流程蓝图型节点在本章内先绘其图，再按其图逐节点成章

**节点类型为子流程蓝图时，其章节先绘制该子流程图，然后照根文档同一套规则在其下完成子流程图每个节点的标准化章节撰写**——即本册 F01–F07 全部适用于该子流程图及其节点章节，层级随之加深一级。判据有两条：**图先于节点章**——该章节内子流程图出现在其节点章节之前；**递归完整**——对本子流程图重复 F06 的覆盖判据，其每个节点都能在更深一层找到恰好一个对应章节，并可继续向下递归，直到不再出现子流程蓝图型节点。

**边界与例外**

- **递归无独立规则**：子流程图不另立一套撰写规范，只是同一套规则在同一节点章节内重演；本册不因层级加深而改写。
- **递归有终点**：展开到某层的子流程图不再含子流程蓝图型节点时，该分支的递归到此结束；本册不设深度上限，图的终止由 F05 的可达性判据保证。
- **章节层级随之加深一级**：节点详述章节由 h2 降为 h3 等，深度由嵌套层数决定；标题所取的标识符仍是唯一的对应锚点（见 F03、F06）。
- **只承载自己的图与节点章节**：本节点章节内的子流程图由其自身承载，不再占用文档别处的章节。
- **F02 的拆图判据在此兑现**：判据规定"须另起一图方能讲清"的节点即属子流程——该节点在图中取子流程蓝图型，其图在本章内绘制。
