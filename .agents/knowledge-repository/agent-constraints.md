# Agent 行为约束

## C-01 不以历史记录论证应当性

- **模态**: must_not
- **scope**: 为规范性结论选取论据
- **动作**: 以历史记录充当规范性结论的论据
- **产出物**: 规范性结论及其论据
  - **形态**: 结论正文，及其点到的每一处依据；依据以现状证据承载——当前源码、当前配置、当前目录结构，或描述现在的命令输出
  - **判定口径**: 结论正文不出现以历史记录承载论证的记号——“当年如此”“历来如此”“按惯例一直如此”“依据变更记录”“按照提交历史”一类词面；结论点到的每处依据都能解析到一个现存对象（现存文件路径、可复算的命令、当前配置项）
  - **语义判据**: 结论的支撑是否取自历史记录——历史记录指一切叙述“过去发生／决定了什么”的记录：版本变更记录、提交历史、历史工单与缺陷记录、会议纪要与讨论存档、代码内以文字标注的历史说明；以任何载体、任何途径取得历史记录用于论证，同判，禁令锚在**结论类型**上，载体只是样张。用户要求查阅历史记录只授权取来源，不使“当年如此故现在应当”成立——论证的合法性与是否获准调取正交
  - **判定边界**: 回答“何时引入、是否发生过、当时如何”这类事实性问题、以及生成排查线索的场合不由本条判定；工作区状态类命令（git status、git diff 等）描述现在而非过去，不属历史记录；以历史记录替代当前状态这一行为不由本条判定，归 [C-05](#c-05-不以历史记录替代当前状态)

## C-02 手写代码不写注释

- **模态**: must_not
- **scope**: 由工程参与者撰写或维护的源码
- **动作**: 以注释语法承载写给人的解释性内容
- **产出物**: 源码文本
  - **形态**: 源码中只存在工具指令形态的注释——类型抑制、lint 指令、shebang、构建与格式化指令；不存在写给人的解释性内容
  - **判定口径**: 逐处取出源码中以注释语法写下的文本（行注释、块注释、文档注释），每处都能点名一个人以外的工具消费者；字符串字面量与正则等上下文中的同类字符不计入
  - **语义判据**: 该处文本的消费者是否为工具——写给人的解释性内容即违规；设计背景与告诫写入知识库，能以命名与结构自表达的优先改代码本身；以注释形式保留的废弃代码同判，它既非指令也非解释
  - **判定边界**: 拷入的第三方代码与构建生成产物中的既有注释不由本条判定，本条只约束自己撰写或维护的代码；禁令锚在“以注释语法承载解释性内容”的用途上，不在文本匹配

## C-03 长期价值优先于成本

- **scope**: 为方案作取舍
- **动作**: 按长期维护负担、复杂度债务与演进能力裁决方案取舍
- **产出物**: 取舍结论
  - **形态**: 结论正文，写明所选方案与计入的成本项；短期执行成本不作为否决所选方案的理由
  - **判定口径**: 结论点名所选方案与至少一项长期成本分量（长期维护负担、复杂度债务、后续演进的阻力、认知负担、故障半径）；“本次多花的工时”“多写的代码行”“多跑一次的测试与构建”一类词面不出现在否决理由中
  - **语义判据**: 同一动作同时呈现两侧时，归类是否按“后续是否重复收取”这一轴作出，而非按本次付出多少；所选方案能否由当前需求导出——改动范围大、抽象层多、设计更通用均不导出长期正确；紧急处置可先做、论证后补，但处置本身仍须经长期正确性裁决通过，以“来不及论证”“先上线再说”要求放行无效
  - **判定边界**: “长期正确”的证明本身不由本条判定，由承载该工程自身准则的决策与审核条目承担

## C-04 不转述可自行取回的事实

- **模态**: must_not
- **scope**: 正文拟写入读者能从工程本身（源码、配置、目录结构、命令输出）自行取回的事实
- **动作**: 把读者能从工程本身自行取回的取值写成结论
- **产出物**: 承载该事实的正文表述
  - **形态**: 与被观测对象同源的取回路径——可复算的命令、指向单一事实源的指针、成员穷举规则；值可得而权威不可得时写契约本身；由设计导出的取值直接写出；取回路径取命令、指针还是成员穷举中的哪种形态，由承载该事实的对象自身决定
  - **判定口径**: 逐处取出表述中的取值，每处都能在提交的工程内解析到一个承载它的现存对象——现存文件路径、可复算的命令、当前配置项；表述不出现“约／大约／估计／据现有信息”与数字同现的复述形态
  - **语义判据**: 对每处事实表述施加删除测试与同步义务测试——删掉该段文字后读者仍能自行取回同一事实者判为转述；该事实变更时负有同步义务者是工程本身者判为副本；同一事实的第二种表示同判，其高发形态是镜像同一事实的两处文字，以及跨生命周期两个平面各自记一份的同一取值；同一事实有多个可能来源时，其归属方取权威最强的那个来源；被写入的取值是否即权威、不得擅改——权威归属落在工程本身之外时该契约必须写出；数字与计数只是副本最常见的载体，不构成禁令的运行范围；把取值改写为取回路径时不连同该事实一起删除
  - **判定边界**: 由设计导出的常量（上限、时间窗、阈值）与取舍结论不由本条判定——工程本身只记录它取值几何，不记录它是决定；标识符与序号、不随实现漂移的路径片段不由本条判定；无工程访问权的读者（发布物、归档）读到的复述不由本条判定，但须标出来源与冻结时刻；本条与文档行文层的同命题条目——[文档撰写规范的 D-02](../skills/doc-writing/reference/doc-writing-constraints.md#d-02-正文不转述可自行取回的事实)——分处两层：该条判文档正文的行文表述，本条判工程内行为所产出的结论与正文；二者命题同源，同一对象只由其中一层判定，不重复计入

## C-05 不以历史记录替代当前状态

- **模态**: must_not
- **scope**: 回答关于当前状态的问题
- **动作**: 以历史记录替代当前状态
- **产出物**: 关于当前状态的回答及其依据
  - **形态**: 回答，逐条断言都在当前状态中有其依据对象——当前源码、当前配置、当前目录结构、当前命令输出
  - **判定口径**: 每条断言点名其在当前状态中的依据对象；“据提交历史”“根据变更记录”“当时的记录显示”一类以历史记录承载当前状态断言的词面不出现
  - **语义判据**: 该断言的依据能否从当前状态直接取回而实际改用历史记录——能取回却改用者即违规，当前状态不可得时才落到例外；历史记录中出现的现象可用于生成待验证假设，但假设的结论仍须回到当前状态取证；以任何载体（命令行、托管平台界面、接口、归档文档）取历史记录替代当前状态，同判，禁令锚在**来源选择**上，载体只是样张
  - **判定边界**: 用户明确要求查阅历史记录、问题本身就是关于过去的（“何时引入、是否发生过、当时如何”，或为解释当前可观测的失败而须知道某变更何时引入），或依据当前状态不可得时，不由本条判定；范围限于该问题所需，不得由它扩张为对当前状态的依据，且回答里须说明数据来源；描述现在的查询（工作区状态、现状差异）产出的是当前状态，正在主句要求之列

## C-06 按领域索引获取知识

- **模态**: must
- **scope**: 执行需要领域知识的任务
- **动作**: 按序执行（索引和工具能力判定结果决定后续取知路径）
  - ① 仅检查与任务领域对应的 domain knowledge 索引是否存在
  - ② 索引存在时，核对对应 domain agent 声明的 toolsets 是否足以支持任务目标；匹配时启动 domain agent，装载索引指向的领域知识并完成任务；不匹配时不启动 domain agent，并从知识库之外获取完成任务所需知识；索引不存在时也从知识库之外获取完成任务所需知识
  - ③ 只读取完成任务所需且由所选路径明确指向的内容，不主动读取其他内容
  - ④ 完成任务后，询问用户是否需要创建工具并在领域知识中留痕
- **产出物**: 基于所选知识路径完成的任务结果及后续询问
  - **形态**: 任务结果及其领域知识来源，并在任务完成后询问用户是否需要创建工具和在领域知识中留痕
  - **语义判据**: 仅当对应 domain agent 的 toolsets 足以支持任务目标时才启动；索引不存在或 toolsets 不匹配时不启动 domain agent，改从知识库之外获取所需知识；两种路径均不主动读取与任务无关或未由路径指向的其他内容；任务完成后须询问用户是否需要创建工具并在领域知识中留痕，不得擅自代用户决定
