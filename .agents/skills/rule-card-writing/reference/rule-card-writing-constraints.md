# 规则卡片与规范册撰写规范

> **范围**：本文规定两件事。其一，**单条规则卡片怎么落笔**——[§0](#0-记号与通则) 至 [§4](#4-禁止字段与禁止形态) 给出字段全集的标签、类型、基数、必填性、取值约束与禁止形态；这段是**元规范**，它定义卡片格式与共享登记，其产物即格式与登记本身，自身不承载规则卡片。其二，**规范册怎么组**——[§5](#5-册层规则) 给出册正文的构成、新条目准入、册级取用范围、条目落笔次序与缺口登记；该章自身即**一册**，其正文只由并列的规则卡片构成。两段体裁不同，各自的判据不得互相套用。
> **读者与判据**：读者是规则卡片与规范册的作者。所有判据须可机械求值，不得依赖读者推断。
> **角色**：**撰写者**写出卡片与册；**解析器**按本文的字段格式把卡片文本读为键值对；**判定者**对单条规则是否成立出具结论，须与撰写者分离；**执行环境层**承载解析器与生成后过滤。四者是角色，不指向任何具体工具、模型或组织。
> **载体前提**：本文的字段格式与解析口径以 **Markdown 行式载体**为前提——卡片由标题行与 `- **<标签>**: <值>` 属性行构成，缩进以空格计。换用其它载体时，[§0.1](#01-标签--字段对照) 至 [§0.5](#05-判定真值源越界即失效) 的文本形态须整体重述；机制层的义务（必填核心、判定真值源、登记的封闭性）不随载体改变。
> **机制层与实例层**：本文的**机制**对任何以规则卡片承载约束的体系成立；本文同时承载**所属体系的实例登记**——[F-01](#f-01-id--规则标识) 的前缀行与 [§6](#6-缺口) 的缺口条目。其它体系复用本文时保留机制、整表替换实例行，实例的解析落在该体系自己的登记处。

## 0. 记号与通则

### 0.1 标签 ↔ 字段对照

规则卡片由**标题行**加若干**属性行**构成。一行一个属性，格式 `- **<标签>**: <值>`；标签与冒号之间无空格，冒号后一个空格。

| # | 字段 | 文本标签 | 卡片基数 | 必填性 |
|---|---|---|---|---|
| 1 | `id` | 标题行首段 | 1 | 必填 |
| 2 | `title` | 标题行次段 | 0..1 | 选填 |
| 3 | `modality` | 模态 | 0..1 | 条件必填 |
| 4 | `actor` | 主体 | 0..1 | 条件必填 |
| 5 | `when` | when | 0..1 | 条件必填 |
| 6 | `scope` | scope | 0..1 | 条件必填 |
| 7 | `action` | 动作 | 1 | 必填 |
| 8 | `artifact` | 产出物 | 1 | 必填 |
| 9 | `external_exceptions` | 外部例外 | 0..* | 条件必填 |
| 10 | `overridable` | ——（不单独成行） | 0..1 | 条件必填 |
| 11 | `coverage_point` | 覆盖点 | 0..1 | 条件必填 |
| 12 | `overrides` | 覆盖 | 0..* | 条件必填 |
| 13 | `layer` | 层 | 0..1 | 条件必填 |
| 14 | `failure_behavior` | 失败行为 | 0..1 | 条件必填 |
| 15 | `dependencies` | 依赖 | 0..* | 条件必填 |
| 16 | `why` | `why:nb` | 0..1 | 选填 |
| 17 | `examples` | 示例 | 0..* | 选填 |

必填核心为 **3 个槽位 / 5 个字段**：指称 ID 槽（`id`）、适用性槽组（`when` + `scope`）、动作 + 产出物槽（`action` + `artifact`）。

### 0.2 子标签登记（封闭集合）

一个字段要表达**多个并列维度**时，用缩进 2 空格的子行承载，格式 `- **<子标签>**: <值>`。下表是子标签的**封闭登记**，也是**唯一登记处**：[§2](#2-字段规则定义) 各字段不再复制本表内容，只指向本表。未登记的子标签名不合法，解析器据本表校验。**凡承载语义的构件都必须在本表或 [§0.1](#01-标签--字段对照) 中有一席之地**——没有登记处的语义只能挤进字段值内，从而使该字段失去可机械求值性。

| 父字段 | 子标签 | 类型 / 基数 | 必填性 | 取值约束 |
|---|---|---|---|---|
| `artifact` | `形态` | `string` / 1 | 必填 | 产出物的**书写格式描述**（自由文本）：写清完成时外部看到的载体长什么样（如"数组，每项含 {变更ID, 违反的基线条款, 证据}"）。**只承载格式，不承载判据**——判据归 `判定口径` 与 `语义判据` |
| `artifact` | `判定口径` | `string` / 0..* | 条件必填 | **须可机械求值**：正则、计数、存在性；与「语义判据」至少出现其一 |
| `artifact` | `语义判据` | `string` / 0..* | 条件必填 | 无法机械求值的谓词；**须显式给出，不得默认通过**；与「判定口径」至少出现其一 |
| `artifact` | `判定边界` | `string` / 0..* | 条件必填 | 本条判定**不含**的对象；该判定由他条承担时写出其规则 ID |
| `scope`（`form = boolean`） | `连接` | `Operators` / 0..1 | 条件必填 | 显式布尔标记；`>3` 合取或含 `or` 时必填 |
| `action`（`form = goal_state_invariant`） | `不变量` | `string` / 0..* | 条件必填 | 终态成立期间须保持的谓词 |
| `coverage_point` | `覆盖内容` | `string` / 0..1 | 选填 | 覆盖内容指针，可外置为强引用 |
| `failure_behavior` | `行为` | `string` / 1 | 必填 | 具体行为描述（`模式` 取 `fail_safe` / `fail_loud`，由顶层行值承载） |
| `dependencies` | `权威源` | `string` / 1 | 必填 | 术语的权威承载位置 |
| `dependencies` | `降级行为` | `string` / 1 | 必填 | 未解析时的显式行为，须为 `fail_loud` |
| `dependencies` | `内联` | `string` / 0..1 | 条件必填 | 仅限不可推断 ∧ 不可解析者 |
| `examples` | `用途` | `ExamplePurpose` / 1 | 必填 | `shape_anchor` / `satisfiability_witness` |

**并列 ≠ 择一**：同一父字段下的多个子标签**并存**（`产出物` 可同时有「形态」「判定口径」「语义判据」「判定边界」四维），与 `form` 式的**择一**形态不同——择一由父字段的 `form` 承载，并列由子标签承载。二者不可互相套用。

### 0.3 文档层定义的文本形态

条目的可省略字段有**文档层默认值**，其文本形态固定为下表，由文档自定一处，条目不再复述。未登记的文档层定义项不合法；引用某个文档层定义项时，其取值来源即本表。

| 定义项 | 文本形态 | 缺省语义 |
|---|---|---|
| 触发事件 | 属性行 `- **when**: <事件>` | 触发即适用 |
| 默认模态 | 属性行 `- **模态**: <Modality>` | `must` |
| 模态词面对照表 | 三列表格：模态 / 词面 / 语义 | `should` 与 `may` 的词面语义由本表锚定 |
| 主体模式 | 属性行 `- **主体模式**: single` 或 `multi` | `single` |
| 默认主体 | 属性行 `- **主体**: <ActorRef>` | 单主体文档下的唯一主体 |
| 层序表 | 两列表格：层 / 序（由高到低） | 无层序；强度只由 `模态` 与 `覆盖` 决定 |

### 0.4 撰写通则

| 通则 | 内容 |
|---|---|
| 省略 | 条件必填 / 选填项在触发条件不成立时**整行不出现**，不得留空标签、不得写占位符 |
| 注释 | `#` 起至行尾**仅作说明，不参与判定**；不得承载唯一信息 |
| 子标签 | 缩进 2 空格续行，格式 `- **<子标签>**: <值>`；子标签名须为 [§0.2](#02-子标签登记封闭集合) 的登记成员 |
| 分隔 | 一个字段内的多个维度**各占一行子标签**；**不得在字段值内自造分隔记号**（如「X：」「Y：」）来堆放并列维度 |
| 大小写 | 字段名一律 ASCII `snake_case`；枚举值一律 ASCII 小写短码 |
| 求值 | 文本形式逐行解析为键值对，字段名与 [§0.1](#01-标签--字段对照) 的顶层属性表一一对应，子标签名与 [§0.2](#02-子标签登记封闭集合) 一一对应 |

### 0.5 判定真值源（越界即失效）

| 判定输入 | 允许来源 |
|---|---|
| 生效条件 | `when`、`scope` |
| 强度 | `modality` |
| 行为 | `action` |
| 完成判据 | `artifact` 及其子标签（`形态`／`判定口径`／`语义判据`／`判定边界`） |
| 胜负 | `overrides` + 文档层序表 |
| **不参与判定** | `title`、`layer`、一切结构标签与注释 |

**判定分两层，两层正交**：`判定口径` 给出可机械求值的部分，`语义判据` 给出无法机械求值的谓词。两者的处置不同——机械层由判定者逐项求值；语义层**不表示"可以跳过"**，判定者须给出判定与理由并单列，无法判定时显式列出交还使用者，**不得计入通过项**。机械层通过不赦免语义层不通过。`判定边界` 不参与"是否成立"的判定，它界定判定的**范围**：边界内不成立即违规，边界外不由本条判定。

> 推论：写在注释、标题与层标签里的任何限制都是**装饰**，不具备约束力。要生效就必须落在上表允许的字段里。

## 1. 规则卡片模板

条件不成立的行**整行删除**，不留空值。

```markdown
{{heading_level}} {{id}} {{title}}
- **模态**: {{modality}}      # modality；偏离默认 must 时才写
- **主体**: {{actor}}         # actor；多主体文档才需声明
- **when**: {{trigger_event}} # 触发事件；省略即"触发即适用"
- **scope**: {{scope}}        # 适用域；省略即全集（须与兜底显式区分）
- **动作**: {{verb}} {{object}}
- **产出物**: {{artifact_name}}
  - **形态**: {{artifact_shape}}      # 必填
  - **判定口径**: {{rubric}}          # 可机械求值；与语义判据至少出现其一
  - **语义判据**: {{semantic}}        # 不可机械求值；须显式给出，不得默认通过
  - **判定边界**: {{boundary}}        # 本条判定不含的对象
- **外部例外**: {{ref_id}}     # 可重复；例外源不在本条内时
- **覆盖点**: {{point_id}}     # 本条可被他条覆盖时（隐含 overridable = true）
  - **覆盖内容**: {{content_ref}}  # 覆盖内容可外置时
- **覆盖**: {{rule_id}}        # 可重复；只写正向
- **层**: {{layer}}            # safety / policy / style；应尽量避免
- **失败行为**: {{mode}}       # fail_safe / fail_loud
  - **行为**: {{behavior}}       # 本条有外部依赖时
- **依赖**: {{term_id}}@{{version}}
  - **权威源**: {{authority_source}}
  - **降级行为**: {{unresolved_behavior}}  # 须为 fail_loud
  - **内联**: {{inline_definition}}        # 仅限不可推断 ∧ 不可解析者
- **why:nb**: {{goal_criterion}}  # 仅适用集开放时
- **示例**: illustrative {{example}}  # 仅谓词无法闭合时
  - **用途**: {{purpose}}          # shape_anchor / satisfiability_witness
```

**并列维度的承载**：`产出物` 的四个子标签可**同时出现**，各自一行；`判定口径` 与 `语义判据` 至少出现其一（二者都出现时两层正交，机械层通过不赦免语义层）。判定与产出物的界面不得互串：`判定口径` 之外的维度不得塞进 `动作` 值内。

**标题行的级别**：`{{heading_level}}` **由文档自身的层级结构给定，不由条目自携**，且同一文档内全部条目的级别一致。级别是**该文档中承载条目的那一层标题**：条目直接承载于文档最上层时，取文档 H1 的下一级（H1 为 `#`，条目即 `##`）；条目承载于某个分组标题之下时，取其所在分组的下一级。缺省 `###`——即未作声明且文档存在分组标题时的取值。级别不写进任何属性行，读者从同一文档内既有的条目标题行即可读出。该级别同样适用于 [§5](#5-册层规则) 的卡片：[§5](#5-册层规则) 作为册时，其条目承载于该章标题之下，取 `###`。

## 2. 字段规则定义

### F-01 `id` —— 规则标识

| 项 | 定义 |
|---|---|
| 文本载体 | 标题行首段：`{{heading_level}} {{id}} {{title}}`；级别由文档层级结构给定，全文档一致 |
| 类型 / 基数 | `RuleId` / 1 |
| 必填性 | **必填**（结构校验失败条件之一，缺失即不合法） |
| 取值约束 | 受控 ASCII 短码 + 固定前缀，形如 `R-014`；正则 `^[A-Z][A-Z0-9]{0,7}-[0-9]{2,4}$`；须正则化，逐字复制不产生形变；全域唯一 |

**前缀登记（封闭集合）**

「全域唯一」的范围是**采用本文的全部规范册**，而非单册。前缀须在本表登记后方可使用，未登记的前缀不合法——某前缀只归一个语义域：两个册子复用同一前缀时，相同的编号会在两处指向不同语义的规则，使 `overrides[]`、`external_exceptions[]` 的引用无法唯一解析。

下表是**所属体系的实例登记**：机制（前缀封闭、一前缀一语义域、登记后方可使用）对任何体系成立，行是该体系当前的占用。其它体系复用本文时整表替换为自己的占用，机制不动。**语义域是该前缀的专属管辖范围，即"占用者"**——登记语义域即登记占用，不另设占用者列。

| 前缀 | 语义域 |
|---|---|
| `R-` | 通用规则卡片 |
| `S-` | 组册与增补 |
| `P-` | 流程类文档的图与节点结构 |
| `D-` | 知识库与指令类文档的正文表述约束 |
| `C-` | agent 执行期行为约束 |

上表是本体系当前的占用。新增占用时的准入判据（何时需要新前缀、何时应复用既有前缀）尚无权威承载，登记为 [§6 缺口 10](#6-缺口)；在缺口闭合前，新增占用只允许追加行，不得复用既有前缀。

本文 [§2](#2-字段规则定义) 内 `F-xx` 形式的编号是**字段定义的章节序号**，不是规则卡片 ID——它们不出现在条目标题行上，也不得被任何 `overrides[]`／`external_exceptions[]` 引用。规则卡片 ID 与字段定义章节号分属两个命名空间，不得互相代替。

**撰写规则**

1. 发布后**不得重用、不得改义**：即便原条被删除，该 ID 也不得分配给新语义。
2. 与正文语义无关：不得把语义压进 ID 试图承载信息。
3. 不得由 `title` 替代：`title` 不参与判定，也不得充当引用句柄。

**参与判定**：`id` 是引用完整性的锚点——`overrides[]`、`external_exceptions[]` 都指向它。`id` 自身不改变规则强度或适用范围。

### F-02 `title` —— 锚标题

| 项 | 定义 |
|---|---|
| 文本载体 | 标题行次段 |
| 类型 / 基数 | `string` / 0..1 |
| 必填性 | 选填 |
| 取值约束 | 无结构约束；服务于人类阅读与检索 |

**撰写规则**

1. **不参与判定**：标题与规则强度、适用范围、执行后果均无关。
2. **不得充当引用句柄**：需要被引用的对象必须是有 ID 的规则或命名谓词，不得用标题引用。
3. 允许在标题中做人类可读的概括，但概括与字段内容不一致时**以字段为准**。

### F-03 `modality` —— 模态

| 项 | 定义 |
|---|---|
| 文本标签 | `模态` |
| 类型 / 基数 | `Modality` / 0..1 |
| 必填性 | **条件必填**：取值偏离文档默认 `must` 时 |
| 取值约束 | 四值封闭枚举，见下表。缺失即按文档默认 `must` |

| 值 | 语义 |
|---|---|
| `must` | 未标注时的默认值 |
| `must_not` | 独立取值；**否定落在模态位而非动作位** |
| `should` | 词面语义由**文档层封闭对照表**锚定 |
| `may` | 词面语义由**文档层封闭对照表**锚定 |

**撰写规则**

1. 模态是**唯一真值源**，由条级自携；文档层只提供默认值与词面对照表，不得在条级另立语义词表。
2. `must_not` 的动作**不得点名被禁对象的字面**，须改写为**类别级**或**正面等价**表述。
3. 安全关键项须配生成后过滤——该过滤由执行环境层承载，**不是本结构的字段**。
4. 第三值（如绝对数值强度）不存在，只能在四值枚举内取值。

### F-04 `actor` —— 执行主体

| 项 | 定义 |
|---|---|
| 文本标签 | `主体` |
| 类型 / 基数 | `ActorRef` / 0..1 |
| 必填性 | **条件必填**：文档为多主体 |
| 取值约束 | 执行主体标识，**必须可由文档层解析**；单主体文档缺省取文档默认（`default_actor_mode = single`） |

**撰写规则**

1. 声明本条**对谁生效**；主体不同则规则不适用，而非强度变化。
2. 引用完整性：解析不到的主体标识不得写入，须先在文档层登记。
3. 单主体文档下省略本行，不写"全体"之类的兜底词。

### F-05 `when` —— 触发事件

| 项 | 定义 |
|---|---|
| 文本标签 | `when` |
| 类型 / 基数 | `TriggerEvent` / 0..1 |
| 必填性 | **条件必填**（适用性槽组之一） |
| 取值约束 | 可观测事件：在**时刻上"发生"**。缺失即"规则触发即适用" |

**撰写规则**

1. **不得写状态**。状态（"处于…中"、"已启用"）属于 `scope`，此处只接受事件。
2. 判据须可观测：能被外部判定者观察到"发生了"，而非需要推断。
3. 执行时序**不属于本字段**，也不属于适用性槽——时序归 `action` 槽（如 `ordered_steps`）。
4. 与 `scope` 的分工：`when` 管"何时启动"，`scope` 管"在什么域与前置状态下适用"；二者构成适用性槽组，缺省语义不同（`when` 缺省 = 触发即适用，`scope` 缺省 = 全集）。

### F-06 `scope` —— 适用域与前置状态

| 项 | 定义 |
|---|---|
| 文本标签 | `scope` |
| 类型 / 基数 | `Scope` / 0..1 |
| 必填性 | **条件必填**（适用性槽组之一） |
| 取值约束 | 适用域与前置状态：在区间内**成立**、**可判定**。缺失即全集。形态四选一，不并存 |

| `form` | 含义 | 文本写法 |
|---|---|---|
| `universe` | 无标记全集 | 省略本行；须与"兜底"语义显式区分（见 [§6 缺口 2](#6-缺口)） |
| `atomic` | 单一原子谓词 | `- **scope**: {{谓词}}` |
| `boolean` | 合取/析取组合 | ≤3 合取可分行编号；>3 或含 `or` 必须给连接词行 |
| `scenario_tag` | 全局定义的场景标签 | `- **scope**: {{场景标签名}}`（标签本体在文档层封闭枚举定义） |

**撰写规则**

1. 谓词须**可判定**：取自全局封闭枚举字段，或为自然语言但可机械判定的事实。
2. **例外一律改写为 `scope ∧ ¬P`**，由原子谓词取反承担。**不设 `except` 字段**：
   - 本地可判定的例外写在 `scope` 内，**不得**写成外部例外。
   - 例：`- **scope**: 变更涉及生产环境配置  # ¬P（非生产环境）即不适用`
3. `operators` 是**显式结构标记**，长度为 `conjuncts.length - 1`；`>3` 项或 AND/OR 混合时**必须**给出。写法：`- **连接**: (① AND ②) OR ③`。
4. `form = universe` 的"无标记全集"**须与"兜底"语义显式区分**；区分载体尚未定义，登记为 [§6 缺口 2](#6-缺口)。

**子结构写法**

```markdown
# boolean，≤3 合取
- **scope**: 同时满足全部三项：
  - ① 变更涉及生产环境配置
  - ② 变更已通过代码评审
  - ③ 变更窗口在维护期内

# boolean，>3 或 AND/OR 混合，必须给 operators
- **scope**: 显式布尔组合
  - ① 变更涉及生产环境配置
  - ② 变更已通过代码评审
  - ③ 触发人为发布工程师
  - **连接**: (① AND ②) OR ③
```

**禁止形态**

- 以自然语言"或" / "和/或"表达析取（须用带 `operators` 的 `boolean`）。
- 以触发词 / 关键词表表达谓词（那既非事件也非可判定事实）。
- 嵌套否定。
- 把执行时序写进本槽。

### F-07 `action` —— 动作

| 项 | 定义 |
|---|---|
| 文本标签 | `动作` |
| 类型 / 基数 | `Action` / 1 |
| 必填性 | **必填** |
| 取值约束 | 形态六选一，**非当前形态的字段不得出现**；抽象度固定在"**工具无关的具体动作级**" |

| `form` | 含义 | 文本写法 |
|---|---|---|
| `imperative_core` | 祈使核 `verb` + `object` | `- **动作**: {{verb}} {{object}}`（合并为一句） |
| `predicate_constraint` | 可判定谓词 + 判定口径 | 本行承载谓词与口径 |
| `pre_post_assertion` | 完成后必须成立什么 | 本行写 `postcondition` |
| `goal_state_invariant` | 终态谓词 + 不变量 | `- **动作**: 目标状态 — …`，另起 2 空格缩进的子行 `- **不变量**: …` |
| `ordered_steps` | 有序步骤，`minItems: 2` | ①②③ 编号行；**仅当动作间有数据依赖**时使用 |
| `unordered_set` | 无序动作集合，`minItems: 2` | ①②③ 编号行 + 显式声明次序无关 |

`ImperativeCore` = `{ verb: string (必填), object: string (必填) }`。

**撰写规则**

1. 产出物**不写在动作里**，由顶层 `artifact` 承载。`action.form = imperative_core` 时动作核只留 `verb` + `object`。
2. **`ordered_steps` 的准入条件只有一条：步间存在数据依赖。** 仅"看起来有先后"不构成理由；无数据依赖就应写成 `unordered_set` 或并列子句。
3. `unordered_set` 必须显式声明"次序无关"（对应 `order_independent = true`）。
4. 判定与格式输出解耦：**判定依据写在 `action`，格式依据写在 `artifact`**。

**禁止形态**

| 禁止 | 理由 / 合法替代 |
|---|---|
| 意图级表述（"确保一致性"、"消除歧义"） | 不可观测；须落到具体动作 |
| 纯目标状态且动作槽为空 | 缺必填；`goal_state_invariant` 也须给出终态谓词 |
| 程度副词（"尽量"、"适当"） | 不可判定 |
| 工具 / API / 参数级细节 | 抽象度越界，须停在工具无关层 |

```markdown
# ordered_steps：仅当动作间有数据依赖
- **动作**: 按序执行（步间有数据依赖）
  - ① 导出当前生产配置快照
  - ② 以快照为输入逐项比对安全基线清单
  - ③ 以比对结果为输入生成驳回项列表

# unordered_set：显式声明次序无关
- **动作**: 以下动作次序无关
  - ① 校验变更元数据完整性
  - ② 校验变更影响面声明

# goal_state_invariant
- **动作**: 目标状态 — 全部变更项均已判定为通过或驳回
  - **不变量**: 判定过程中不得修改原始变更内容
```

### F-08 `artifact` —— 可观测产出物

| 项 | 定义 |
|---|---|
| 文本标签 | `产出物`（顶层行承载产出物名称） |
| 类型 / 基数 | `Artifact` / 1 |
| 必填性 | **必填** |
| 取值约束 | 完成后**可观测什么**；`action.form = imperative_core` 时与动作核内联 |

产出物是**多维槽位**：名称在顶层行，以下四个子标签 `形态`／`判定口径`／`语义判据`／`判定边界` **并列承载**，各占一行。四者的基数、必填性与取值约束由 [§0.2](#02-子标签登记封闭集合) 统一登记，本节不复制。

**撰写规则**

1. 产出物是"完成"的唯一判据载体：写完 `action` 必须回答"完成时外部能看到什么"。
2. **两个判定维度不得互相替代，也不得混写在同一行**：机械可求值的写 `判定口径`，不可求值的写 `语义判据`。**在 `产出物` 值内自造分隔记号**（如「机械：」「语义：」）堆放两个维度，即违反 [§0.4](#04-撰写通则) 的分隔通则——那是子标签缺位时的补丁，不是合法写法。
3. **`语义判据` 不是免检项**：它无法机械求值，但必须显式给出；判定者须作出判定并写明理由，在结论中单列，无法判定时交还使用者。**把 `语义判据` 略去不计，等于宣称一个无法核实的条目已通过。**
4. **`判定边界` 是把"不判定"从判据里拆出来的归宿**：写明本条不判定的对象及其承担者，读者据此知道该由哪条判定，而不是从判据正文里读出一句"本条不判定…"。边界外的违规不由本条负责，但**边界内不得留白**。
5. 格式依据写在本字段，判定依据写在 `action`——不得把格式要求塞进 `artifact` 子标签之外的地方，也不得把判定依据塞进 `action` 的格式描述里。

### F-09 `external_exceptions` —— 外部例外

| 项 | 定义 |
|---|---|
| 文本标签 | `外部例外`（可重复，每项一行） |
| 类型 / 基数 | `StrongRef[]` / 0..* |
| 必填性 | **条件必填**：例外源不在本条内 |
| 取值约束 | 命名谓词 ID 或规则 ID 的**强引用**；固定命名空间前缀；**禁自然语言** |

**撰写规则**

1. **本地可判定的例外不得写在此处**——它们属于 `scope` 的 ¬P。
2. 引用必须解析到规则 ID 或命名谓词 ID；不可解析时按本条 `failure_behavior` 处理。
3. 逐项一行，不合并、不写说明文字。

### F-10 `overridable` —— 可覆盖性

| 项 | 定义 |
|---|---|
| 文本载体 | **不单独成行**，由"覆盖点"行的存在性隐含 |
| 类型 / 基数 | `boolean` / 0..1 |
| 必填性 | **条件必填**：本条可被他条覆盖 |
| 取值约束 | 为 `true` 时 `coverage_point` 变为**必填** |

**撰写规则**

1. `overridable` 可由 `coverage_point` 的存在性推导，故**不写行**。
2. 写"覆盖点"行即等价于声明 `overridable = true`；不写即未被覆盖。

### F-11 `coverage_point` —— 覆盖点

| 项 | 定义 |
|---|---|
| 文本标签 | `覆盖点` |
| 类型 / 基数 | `CoveragePoint` / 0..1 |
| 必填性 | **条件必填**：`overridable = true`（即写出本行） |
| 取值约束 | 顶层行值为覆盖点标识，必填；子标签 `覆盖内容` 的基数、必填性与取值约束由 [§0.2](#02-子标签登记封闭集合) 登记 |

**撰写规则**

1. **被覆盖方必须内嵌自身可被覆盖的事实与覆盖点**——即本条内必须出现"覆盖点"行。覆盖关系不能只从对方单边可见。
2. 覆盖内容可外置为强引用，以避免条件在多处复制后漂移。
3. 覆盖点的形态与命名规则尚未定义，登记为 [§6 缺口 3](#6-缺口)。

### F-12 `overrides` —— 正向覆盖指针

| 项 | 定义 |
|---|---|
| 文本标签 | `覆盖`（可重复） |
| 类型 / 基数 | `RuleId[]` / 0..* |
| 必填性 | **条件必填**：存在定向冲突 |
| 取值约束 | **只写正向指针**，列出被本条压制的规则 ID；去重；**不得自指** |

**撰写规则**

1. **只写正向**：本条写"我压制谁"，被压制方不写"我被谁压制"。
2. 目标必须是**已存在**的规则 ID；不得自指；同一 ID 不得重复出现。
3. 值只写规则 ID，**不得重复标签语义**（不要写 `overrides R-021`，只写 `R-021`）。
4. 绝对数值优先级（`priority`）不存在；强度由条级 `modality` + `overrides` + 文档层序表共同决定。

### F-13 `layer` —— 层标签

| 项 | 定义 |
|---|---|
| 文本标签 | `层` |
| 类型 / 基数 | `Layer` / 0..1 |
| 必填性 | **条件必填**：文档存在分层优先级；**应尽量避免使用** |
| 取值约束 | 封闭小集合：`safety` / `policy` / `style`。**不参与判定** |

**撰写规则**

1. 本字段是**分类标签，不参与判定**：写 `safety` 不会让规则更强，强弱只能由 `modality` 与 `overrides` 产生。
2. 优先用 `modality` + `overrides` 表达优先级；只有在文档确实存在分层序表时才写本行。
3. 封闭集合的扩展机制尚未定义，登记为 [§6 缺口 4](#6-缺口)。

### F-14 `failure_behavior` —— 失败行为

| 项 | 定义 |
|---|---|
| 文本标签 | `失败行为`（顶层行值为 `模式`） |
| 类型 / 基数 | `FailureBehavior` / 0..1 |
| 必填性 | **条件必填**：本条有外部依赖 |
| 取值约束 | 顶层行值即 `模式`，必填，取 `fail_safe` 或 `fail_loud`；子标签 `行为` 的基数、必填性与含义由 [§0.2](#02-子标签登记封闭集合) 登记 |

| `模式` 取值 | 含义 |
|---|---|
| `fail_safe` | 默认填充 |
| `fail_loud` | 拒绝执行 |

**择一判据（按失败方向）**

- 存在**消费方可察觉的**安全默认 → `fail_safe`。
- 默认会导致**静默误解** → `fail_loud`。

判据锚在**默认值出错时消费者能否察觉**，不锚在消费者的实现品类：把"可察觉"写成某个具体模型或工具能识别，会使本判据随该工具的换代而失效。

**撰写规则**

1. `行为` 必填，须写出具体行为，不得写"报错"这类空泛表述。
2. **有外部依赖就必须写本行**：`external_exceptions` 不可解析、`dependencies` 不可解析时的降级行为都回落到这里。

### F-15 `dependencies` —— 依赖指针

| 项 | 定义 |
|---|---|
| 文本标签 | `依赖`（顶层行值为 `{{term_id}}@{{version}}`，可重复） |
| 类型 / 基数 | `Dependency[]` / 0..* |
| 必填性 | **条件必填**：含外部术语 |
| 取值约束 | 术语 ID + 版本在顶层行；三个子标签 `权威源`／`降级行为`／`内联` 的基数、必填性与取值约束由 [§0.2](#02-子标签登记封闭集合) 统一登记 |

**撰写规则**

1. **判定顺序**：可解析 → 写指针；不可解析但可定义 → 写 `内联`；不可定义 → 降级。
2. 规则不承载知识本体；"自包含"指**可判定地解析**，非字面自足。
3. 禁止在条级写术语本体定义（`内联` 是唯一例外，且受上述双重条件限制）。
4. `version` 的比较语义尚未定义，登记为 [§6 缺口 5](#6-缺口)。

**子结构写法**：`- **依赖**: {{term_id}}@{{version}}`；权威源、降级行为与内联定义各起一行 `- **权威源**: …`、`- **降级行为**: …`、`- **内联**: …`。

### F-16 `why` —— 理由 / 意图

| 项 | 定义 |
|---|---|
| 文本标签 | `why:nb`（`nb` = non-normative） |
| 类型 / 基数 | `WhyBlock` / 0..1 |
| 必填性 | 选填，**仅当适用集开放**：含"等 / 类似 / 视情况 / 合理" |
| 取值约束 | 非规范标记块，须与规范段**物理分离** |

| 子标签 | 基数 | 必填性 | 约束 |
|---|---|---|---|
| （顶层行值） | 1 | 必填 | 理由内容；写成**目标状态 / 验收判据**，不写动机叙事；**禁道义词**（必须 / 不得 / should） |

**撰写规则**

1. 写成"目标是使…成立"一类的**验收判据**，不写"因为历史原因…"一类叙事。
2. **禁道义词**：出现"必须 / 不得 / should"即越界，那些属于规范段。
3. 外推须有本体谓词支撑，**冲突时本体优先**。
4. 适用集闭合时**不写本行**——那时 `scope` 已经说清边界，理由块只会引入不可判定的口径。

### F-17 `examples` —— 示例

| 项 | 定义 |
|---|---|
| 文本标签 | `示例`（可重复；行首必须带 `illustrative`） |
| 类型 / 基数 | `Example[]` / 0..* |
| 必填性 | 选填，**仅当谓词无法闭合**：阈值方向歧义 |
| 取值约束 | 顶层行值为示例内容，必填，**须当规格而非说明对待**，行首固定常量 `illustrative`（**非 exhaustive**）；子标签 `用途` 的基数、必填性与取值由 [§0.2](#02-子标签登记封闭集合) 登记 |

**撰写规则**

1. **反例一旦揭示新边界，应改写 `scope` 谓词，而非保留示例**（谓词优先）。
2. 示例是规格而非说明：读者按示例办事时，示例的效力与谓词同级。
3. 多条示例每项一行，行首均标 `illustrative`；`用途` 为**必填**子标签，须与示例同行组内给出。

**禁止**

- 未标 `illustrative` 的示例；`exhaustive` 标记。
- 输出侧自检型示例。
- 每条规则标配示例。
- 无差别预置全量边界反例。

```markdown
- **示例**: illustrative 跨环境同步时须附带源环境标识
  - **用途**: shape_anchor
- **示例**: illustrative 批量变更须附带批次编号
  - **用途**: satisfiability_witness
```

## 3. 结构约束汇总

### 3.1 触发条件总表

| 字段 / 子标签 | 触发条件 |
|---|---|
| `modality` | 取值偏离文档默认 `must` |
| `actor` | 文档为多主体 |
| `external_exceptions` | 例外源不在本条内 |
| `overridable` + `coverage_point` | 本条可被他条覆盖 |
| `coverage_point.覆盖内容` | 覆盖内容外置为强引用 |
| `overrides` | 存在定向冲突 |
| `layer` | 文档存在分层优先级（**应尽量避免触发**） |
| `failure_behavior` | 本条有外部依赖 |
| `failure_behavior.行为` | 写出 `failure_behavior` 即必填 |
| `dependencies` | 含外部术语 |
| `dependencies.权威源` / `降级行为` | 写出 `dependencies` 即必填 |
| `dependencies.内联` | 术语不可推断 ∧ 不可解析 |
| `why` | 适用集开放（含"等 / 类似 / 视情况 / 合理"） |
| `examples` | 谓词无法闭合（阈值方向歧义） |
| `examples.用途` | 写出 `examples` 即必填 |
| `artifact.判定口径` | 存在可机械求值的判据；与 `语义判据` 至少出现其一 |
| `artifact.语义判据` | 存在不可机械求值的谓词；与 `判定口径` 至少出现其一 |
| `artifact.判定边界` | 本条不判定的对象须交给其他承担者 |
| `scope.连接`（`form = boolean`） | `>3` 合取或含 `or` |
| `action.不变量`（`form = goal_state_invariant`） | 该形态下须给出不变量 |

### 3.2 互斥与择一

| 约束 | 内容 |
|---|---|
| `scope.form` | 四形态**不并存**于同一槽位，`form` 决定该形态专属字段的必填性 |
| `action.form` | 六形态**择一**，非当前形态的字段不得出现 |
| 子标签并列 | 同一父字段下的子标签**并存**（如 `产出物` 的四个子标签）；择一由 `form` 承载，不由子标签承载 |
| 本地例外 | **不设独立字段**（无 `except`）；由 `scope` 的 ¬P 吸收 |
| 覆盖方向 | 只写 `overrides`；**禁止反向指针** |

### 3.3 计数上限

| 约束 | 量级 | 性质 |
|---|---|---|
| 任一条规则在任一执行场景下**同时激活的约束数** | ≤ 5–6 | 经验量级，超出即结构性风险 |
| 同一条内并列的同构子句数 | ≤ 5–7，超出**拆条而非压缩** | 经验量级 |
| `scope.conjuncts` | ≤ 3 纯合取可分行编号；>3 或含 `or` 必须给 `连接` | 硬约束 |
| 必填核心 | 见 [§0.1](#01-标签--字段对照) | 硬约束 |

> 同时激活约束数 = 该条已出现的**顶层字段数** + 已出现的**子标签数**（不含 `id`、`title`，不含 `形态` 这类描述性必填子标签）。子标签是并列维度，与顶层字段同权计入：`产出物` 的四维写全即占四席。

### 3.4 引用完整性

| 引用 | 要求 |
|---|---|
| 规则 ID（任何位置） | 须带 [F-01](#f-01-id--规则标识) 前缀登记表中的已登记前缀，且在全域内唯一解析到一条规则；未登记前缀或解析到多条即不可解析 |
| `overrides[]` | 目标必须是已存在规则 ID；不得自指；去重 |
| `external_exceptions[]` | 必须解析到规则 ID 或命名谓词 ID；不可解析 → 按 `failure_behavior` 处理 |
| `dependencies[].term_id` | 必须可由文档层或执行环境层解析；不可解析 → 执行「降级行为」子标签的取值 |
| `scope.scenario_tag` | 必须是文档层封闭枚举成员 |
| `actor` | 必须可由文档层解析 |

## 4. 禁止字段与禁止形态

| 禁止项 | 合法替代 |
|---|---|
| `except`（本地例外字段） | `scope` 的 ¬P（原子谓词取反） |
| `overridden_by`（反向指针） | 仅写 `overrides` |
| `priority`（绝对数值优先级） | 条级 `modality` + `overrides` + 文档层序表 |
| 未标 `illustrative` 的示例、`exhaustive` 标记 | 行首固定常量 `illustrative` |
| 条级术语本体定义 | `dependencies` 指针（例外：`内联`，限不可推断 ∧ 不可解析） |
| 触发词 / 关键词表 | `scope` 的可判定谓词 |
| 适用性槽中的执行时序 | `action` 槽 |
| 自然语言析取（"或" / "和/或"） | `scope` 谓词（`atomic` 或带 `连接` 的 `boolean`） |
| 嵌套否定 | 原子谓词取反 |
| 自检 / 输出侧判定字段 | 外部判定者 |
| 条级模态语义词表 | 文档层封闭对照表 |
| 绝对数值强度的第三值 | 四值枚举内的取值 |
| **字段值内的自造分隔记号**（「X：」式并列维度） | [§0.2](#02-子标签登记封闭集合) 的具名子标签 |
| **未在 [§0.2](#02-子标签登记封闭集合) 登记的子标签名** | 登记后使用；或改用已登记子标签 |

| **把"本条不判定 X"写进判据正文** | `判定边界` 子标签，写明承担者 |

## 5. 册层规则

### S-00 册正文只由并列的规则卡片构成

- **scope**: 显式布尔组合
  - ① 该**册**以规则卡片承载某类约束——即其条目是"一条规则一张卡片"，条目 ID 取该册在**所属体系登记处**登记的前缀（登记处即 [F-01](#f-01-id--规则标识) 的前缀表）
  - ② 该册有**承载它的标题行**——独立成册时即文档的 H1 标题行，作为章节时即该章节的标题行
  - **连接**: ① AND ②
- **动作**: 把册正文写成若干并列的规则卡片，一个条目一个章节
- **产出物**: 册正文
  - **形态**: 承载标题行之后**直接**是首个条目的标题行，条目之间**依次并列**、无分组。条目取**同一标题级别**，级别由文档层级结构给定（取回 [§1](#1-规则卡片模板) 的标题行级别规则）；条目以下为卡片自身的字段行与子标签行。册正文除承载标题行与条目卡片外，**不含任何其它内容块**——不设册首声明段、不设分组标题、不设缺口章节、不设附录、不设分隔线与引用块等一切非卡片块
  - **判定口径**: 逐行解析文档，凡**不能按字段全集的解析规则解析为卡片构件**的非空行（即非承载标题行、非条目标题行、非字段行、非子标签行、亦非字段值所允许的承载行），判为册正文的多余块，逐处列出其行号与文本；条目之间不得插入其它标题级别
  - **判定边界**: 卡片内部的字段与子标签的正确性不由本条判定，取回 [§2](#2-字段规则定义)；哪些行算卡片构件，由该册的解析规则给定，本条不复制其清单；条目内容承载什么不由本条判定。**定义卡片格式与共享登记的元规范**——其产物即格式与登记本身（如本文 [§0](#0-记号与通则) 至 [§4](#4-禁止字段与禁止形态) 的字段全集与各登记表）——不承载规则卡片，按 [①](#s-00-册正文只由并列的规则卡片构成) 不落入本条，其登记块不由本条判定，册之外的这段前置内容也不由本条判定
  - **语义判据**: 册正文是否恰好由承载标题行与条目卡片构成——读者打开册子即进入条目本身，无须先读一段册级前言才能读到规则；判据锚在**解析单位**上：掺入无法解析为卡片的块后，读者与解析器对"本册有几条规则"不再有统一答案
- **失败行为**: fail_loud
  - **行为**: 出现非卡片块时中止写入并逐处点名该块的行号与类型，不把它改写为卡片内的一行来迁就，也不以"读者需要入口"为由保留册首段落

### S-01 新条目准入

- **scope**: 显式布尔组合
  - ① 向既有规范册新增条目
  - ② 修订既有条目所取的字段与子标签
  - **连接**: ① OR ②
- **动作**: 按序执行（步间有数据依赖）：
  - ① 取本条拟用的字段与子标签，逐个核对是否已在字段全集中登记
  - ② 有未登记者，先在字段全集（[§0.1](#01-标签--字段对照) 与 [§0.2](#02-子标签登记封闭集合) 的登记处）登记其标签、基数、必填性与取值约束，再落笔
  - ③ 按 [S-02](#s-02-册级取用范围不落进册正文) 判定本册的取用范围是否触发册级登记；触发则更新之，使之与本册条目实际使用的名称一致
  - ④ 新条目改变条目间依赖时，按 [S-03](#s-03-条目按依赖次序落笔) 判定该依赖是否触发落笔次序，触发则更新之
- **产出物**: 准入结果
  - **形态**: 新条目本身；未登记名称在字段全集中的新增登记项；取用范围触发 [S-02](#s-02-册级取用范围不落进册正文) 时更新后的册级登记；依赖触发 [S-03](#s-03-条目按依赖次序落笔) 时一并调整条目在册内的先后
  - **判定口径**: 新条目使用的每个字段名与子标签名都能在字段全集中解析到；登记处存在册级取用范围登记时，该登记与本册各条目实际出现的名称双向对应——册内出现的行都在取用项内，且登记列出的每项都在册内以对应形态出现过；新增登记项的标签名不与既有登记重名
  - **语义判据**: 新引入的名称是否承载了既有名称无法承载的语义——与既有名称同义者不新立，改用既有名称
  - **判定边界**: 新条目判据内容本身的成立与否不由本条判定，由该条自己的产出物判定

### S-02 册级取用范围不落进册正文

- **scope**: 某个规范册的取用范围
- **动作**: 不为该册另写取用范围声明，把各行的取舍交回**字段自身的缺省语义与触发条件**裁决
- **产出物**: 册对各行的取舍
  - **形态**: 取舍结果直接体现在条目文本里——用得上的行写出，用不上的行整行不出现；该行不出现即表示其触发条件在本册不成立，读者据该字段的缺省语义（取回 [§0.3](#03-文档层定义的文本形态) 与 [§2](#2-字段规则定义)）即可裁决，**不另设册级声明段**
  - **判定口径**: 册正文内不出现对字段取用范围的册级声明——即没有哪一行以"本册取用/不出现下列字段"为内容的非卡片块；某行是否该出现，逐个字段按其触发条件与本册条目文本判定
  - **语义判据**: 该册的取用范围是否真的无法由条目文本与字段缺省语义推出——可推出者不另立声明，声明一份即造出与该缺省语义并行的第二事实源；仅在确实推不出时才需要外部承载，而该承载不在册正文内
  - **判定边界**: 字段自身的语义、基数的正确性不由本条判定，取回 [§2](#2-字段规则定义)；某个字段按全集规定是否条件必填，也不由本条判定；本条不判定册正文的块集合，册正文的构成归 [S-00](#s-00-册正文只由并列的规则卡片构成)

### S-03 条目按依赖次序落笔

- **scope**: 规范册内的条目集合，且其中存在**落笔位置无法由该条自身取回**的条目——即某条的位置不由它自己的 `形态`／`判定口径`／`判定边界`，也不由它 `动作` 的步骤次序给定，只能由他条反推
- **动作**: 按条目产出物之间的依赖关系确定落笔次序，并**以卡片在册内的物理先后**承载该次序
- **产出物**: 落笔次序
  - **形态**: 卡片在册内的排列次序本身即该次序——被依赖者的卡片排在依赖者的卡片之前。**不另立次序表**：次序表是同一事实的第二处承载，与卡片排列分叉时无从裁决哪一处为准，且它本身即册正文的多余块（见 [S-00](#s-00-册正文只由并列的规则卡片构成)）
  - **判定口径**: 逐个取出存在依赖关系的条目对，被依赖者所在行号小于依赖者所在行号
  - **判定边界**: 次序不是流水线禁令——实际撰写可以迭代，本条只判定卡片排列是否满足偏序；某条的落笔位置已由该条自身的 `形态`／`判定口径`／`判定边界` 或 `动作` 的步骤次序给定时，该依赖不触发本条，不为该条另设约束

### S-04 册内条目都不承载的情形登记为缺口

- **scope**: 落在某个规范册覆盖范围之内的情形，而册内条目都判不了
- **动作**: 把该情形登记为缺口，并写明遇到时的处置方式；登记**不成其为册正文的内容块**
- **产出物**: 缺口登记
  - **形态**: 逐条列出该情形、册内条目承载不了的原因、以及遇到时的处置方式。**落点在册正文之外**——缺口是"本册判不了"的事实，本就不属于任何条目；把它写进册内即破坏册正文的构成（见 [S-00](#s-00-册正文只由并列的规则卡片构成)）。承载点取**所属体系已有的缺口登记处**（本文体系的登记处即 [§6](#6-缺口)），不新增落点
  - **判定口径**: 每条缺口都给出处置方式，而非只描述问题；缺口登记不出现在册正文块集合内
  - **语义判据**: 该情形是否确实落在本册覆盖范围之内——范围之外的情形不登记为缺口
  - **判定边界**: 本条只在触发时产出登记，不要求册内常设缺口章节——册内无此类情形时不产出登记，也不为此设空章节
- **失败行为**: fail_loud
  - **行为**: 册内条目都判不了时中止并列出该情形，不自行发明写法、不在册内补写解释章节

## 6. 缺口

本章即 [§5](#5-册层规则) 册正文之外的缺口登记处，列出尚无权威承载的缺口（1–6 为结构缺口，7–9 与 11 为文档缺口，10 为实例层缺口）。**撰写时遇到这些情形，须显式登记而非自行发明写法**；登记规则见 [S-04](#s-04-册内条目都不承载的情形登记为缺口)：

1. **适用性槽组的存在性校验**：`when` 与 `scope` 均可省略时，如何机械判定"适用性槽组已显式成立"。
2. **"无标记全集"与"兜底"区分的字段载体**：二者须显式区分，但字段名未定义——故 `scope` 省略行的写法在缺口闭合前不具区分力。
3. **`coverage_point` 的形态与命名规则**：仅要求"覆盖点标识"，未给标识的构造规则。
4. **`layer` 封闭集合的扩展机制**：未定义新增层标签的准入。
5. **`version` 的比较语义**：未定义版本 / 哈希的相等与新旧判定口径。
6. **"同时激活约束 ≤ 5–6"的精确计量口径**：为经验量级，非精确常数。
7. **三种形态的可照抄样例**：`scope.form = universe`、`action.form = predicate_constraint`、`action.form = pre_post_assertion` 在 [§2](#2-字段规则定义) 只有描述性写法，无字面样例；它们的形状须照该表描述书写，不得自行发明。其中仅 `universe` 另受缺口 2 阻塞，另两者与缺口 2 无关。
8. **`scope` 谓词的类型登记**：谓词可取自"全局封闭枚举字段"或"可机械判定的自然语言事实"，但枚举字段本身没有登记处——故 `scope.form = atomic` 与 `scenario_tag` 的取值在缺口闭合前无可机械校验的合法集合。
9. **`连接` 子标签的取值域**：类型标为 `Operators` / 0..1，[§0.2](#02-子标签登记封闭集合) 未登记其取值形态（连接词的合法记号与优先级、编号行的引用写法），解析器无法据表校验其取值。
10. **本体系前缀占用的准入机制**：[F-01](#f-01-id--规则标识) 的前缀表是本体系的实例行，但"何时需要一个新前缀、何时应复用既有前缀"的判据未定义——这是**实例层**缺口，其它体系复用本文时自行闭合。
11. **文档层定义项的落笔处与其标签登记**：[§0.3](#03-文档层定义的文本形态) 要求文档层定义"由文档自定一处"，但其中 `主体模式`、`层序表`、`模态词面对照表` 三项的标签未在 [§0.1](#01-标签--字段对照) 顶层表中登记，而 [§0.4](#04-撰写通则)「求值」要求字段名与 §0.1 一一对应——故这三项目前写得出、解析不了。且 [S-00](#s-00-册正文只由并列的规则卡片构成) 禁止册正文出现非卡片块，独立成册的册子其 H1 即承载标题行，前置位置为空，文档层定义在册内无处可落。落笔处与其标签登记方式未定，缺口闭合前不得自行发明。

> **已闭合**：原缺口「形态专属子标签的封闭登记」已由 [§0.2](#02-子标签登记封闭集合) 闭合——子标签的合法集合、文本标签、基数、必填性与取值约束均已登记，解析器可据该表校验子标签名。原缺口「产出物的判定口径无独立子标签」同批闭合：`形态`／`判定口径`／`语义判据`／`判定边界` 四维已登记，「依赖」的 `权威源`／`降级行为`／`内联` 与「失败行为」的 `行为`、「示例」的 `用途` 亦然。
