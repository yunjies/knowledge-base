# 规则卡片撰写规范

> **范围**：本文规定**单条规则卡片怎么落笔**——[§0](#0-记号与通则) 至 [§4](#4-禁止字段与禁止形态) 给出字段全集的标签、类型、基数、必填性、取值约束、结构约束与禁止形态；本文是**元规范**，它定义卡片格式与共享登记，其产物即格式与登记本身，自身不承载规则卡片。**规范册怎么组**不由本文规定，取[规范册撰写规范](../../spec-book-writing/reference/spec-book-writing-constraints.md)（下称**册层规范**）——册正文的构成、新条目准入、册级取用范围、条目落笔次序与缺口登记均以该册为准。两份规范体裁不同，各自的判据不得互相套用。
> **读者与判据**：读者是规则卡片的作者。判据须可机械求值，不得依赖读者推断，**唯一例外是册层规范登记在册的缺口**（见册层规范 [§0.1](../../spec-book-writing/reference/spec-book-writing-constraints.md#01-缺口登记)）——缺口处无权威口径，撰写者按该处明写的处置方式办，**不得自行发明写法**。
> **角色**：**撰写者**写出卡片；**解析器**按本文的字段格式把卡片文本读为键值对；**判定者**对单条规则是否成立出具结论，须与撰写者分离；**执行环境层**承载解析器与生成后过滤。四者是角色，不指向任何具体工具、模型或组织。
> **载体前提**：本文的字段格式与解析口径以 **Markdown 行式载体**为前提——卡片由标题行与 `- **<标签>**: <值>` 属性行构成，缩进以空格计。换用其它载体时，[§0.1](#01-标签--字段对照) 至 [§0.5](#05-判定真值源越界即失效) 的文本形态须整体重述；机制层的义务（必填核心、判定真值源、登记的封闭性）不随载体改变。
> **机制层与实例层**：本文的**机制**对任何以规则卡片承载约束的文档成立；本文不承载任何实例登记——前缀由各承载文档自己的条目标题行给出，不另设登记处。其它文档复用本文时保留机制、自定前缀。**前缀与编号空间按文档各自维护、互不隔离**（见 [F-01](#f-01-id--规则标识)）。

## 0. 记号与通则

### 0.1 标签 ↔ 字段对照

规则卡片由**标题行**加若干**属性行**构成。一行一个属性，格式 `- **<标签>**: <值>`；标签与冒号之间无空格，冒号后一个空格。

| # | 字段 | 文本标签 | 卡片基数 | 必填性 |
|---|---|---|---|---|
| 1 | `id` | 标题行首段 | 1 | 必填 |
| 2 | `title` | 标题行次段 | 0..1 | 选填 |
| 3 | `modality` | 模态 | 0..1 | 条件必填 |
| 4 | `actor` | 主体 | 0..1 | 条件必填 |
| 5 | `when` | when | 0..1 | 条件必填 |
| 6 | `scope` | scope | 0..1 | 条件必填 |
| 7 | `action` | 动作 | 1 | 必填 |
| 8 | `artifact` | 产出物 | 1 | 必填 |
| 9 | `external_exceptions` | 外部例外 | 0..* | 条件必填 |
| 10 | `overridable` | ——（不单独成行） | 0..1 | 条件必填 |
| 11 | `coverage_point` | 覆盖点 | 0..1 | 条件必填 |
| 12 | `overrides` | 覆盖 | 0..* | 条件必填 |
| 13 | `layer` | 层 | 0..1 | 选填 |
| 14 | `failure_behavior` | 失败行为 | 0..1 | 条件必填 |
| 15 | `dependencies` | 依赖 | 0..* | 条件必填 |
| 16 | `why` | `why:nb` | 0..1 | 选填 |
| 17 | `examples` | 示例 | 0..* | 选填 |

**文档层定义项不在本表登记**：它们是文档层定义的构件，不是卡片字段，其**唯一登记处**为 [§0.3](#03-文档层定义的文本形态)（定义项名、所用标签名、文本形态与缺省语义同处一表，不复制）。**本表与 [§0.3](#03-文档层定义的文本形态)、[§0.2](#02-子标签登记封闭集合) 的标签名两两不同名**——同名会让同一行得到两个归属，故 [§0.3](#03-文档层定义的文本形态) 一律使用独有标签名，解析器据标签名即可唯一分流，不依赖位置。本表只登记卡片内的顶层字段；各处标签分属不同登记表，不得互串。

必填核心为 **2 个槽位 / 3 个字段**：指称 ID 槽（`id`）、动作 + 产出物槽（`action` + `artifact`）。三者的"必填"是字面意义——缺失即结构校验失败（[§3.3](#33-计数上限) 的硬约束）。**适用性槽组（`when` + `scope`）不属必填核心**：二者各为条件必填且各带缺省语义（[F-05](#f-05-when--触发事件) 缺省为"触发即适用"，[F-06](#f-06-scope--适用域与前置状态) 缺省为全集），整行不出现即取该缺省值。故槽组的成立无须显式，判定者按缺省语义取值即可。

### 0.2 子标签登记（封闭集合）

一个字段要表达**多个并列维度**时，用缩进 2 空格的子行承载，格式 `- **<子标签>**: <值>`。下表是子标签的**封闭登记**，也是**唯一登记处**：[§2](#2-字段规则定义) 各字段条目不复制本表内容，只指向本表。未登记的子标签名不合法，解析器据本表校验。**凡承载语义的构件都必须在本表或 [§0.1](#01-标签--字段对照) 中有一席之地**——没有登记处的语义只能挤进字段值内，从而使该字段失去可机械求值性。

| 父字段 | 子标签 | 类型 / 基数 | 必填性 | 取值约束 |
|---|---|---|---|---|
| `artifact` | `形态` | `string` / 1 | 必填 | 产出物的**书写格式描述**（自由文本）：写清完成时外部看到的载体长什么样（如"数组，每项含 {变更ID, 违反的基线条款, 证据}"）。**只承载格式，不承载判据**——判据归 `判定口径` 与 `语义判据` |
| `artifact` | `判定口径` | `string` / 0..* | 条件必填 | **须可机械求值**：正则、计数、存在性；与「语义判据」至少出现其一 |
| `artifact` | `语义判据` | `string` / 0..* | 条件必填 | 无法机械求值的谓词；**须显式给出，不得默认通过**；与「判定口径」至少出现其一 |
| `artifact` | `判定边界` | `string` / 0..* | 条件必填 | 本条判定**不含**的对象；该判定由他条承担时写出其规则 ID |
| `scope`（`form = boolean`） | `连接` | `Operators` / 0..1 | 条件必填 | 显式布尔标记；`>3` 合取或含 `or` 时必填。**取值形态**：连接词仅 `and` / `or` 两种，一律 ASCII 小写（[§0.4](#04-撰写通则)「大小写」），优先级 `and` > `or`，分组用半角括号；编号项以 ①②③ 形式引用 `scope` 的行内编号行。`>3` 合取或含 `or` 时本子标签必填 |
| `action`（`form = goal_state_invariant`） | `不变量` | `string` / 0..* | 条件必填 | 终态成立期间须保持的谓词 |
| `coverage_point` | `覆盖内容` | `string` / 0..1 | 选填 | 覆盖内容指针，可外置为强引用（该子标签承载可外置的覆盖**内容**；父行的**标识取值**不参与判定，见 [F-11](#f-11-coverage_point--覆盖点)） |
| `failure_behavior` | `行为` | `string` / 1 | 必填 | 具体行为描述（`模式` 取 `fail_safe` / `fail_loud`，由顶层行值承载） |
| `dependencies` | `权威源` | `string` / 1 | 必填 | 术语的权威承载位置 |
| `dependencies` | `降级行为` | `string` / 1 | 必填 | 未解析时的显式行为，须为 `fail_loud` |
| `dependencies` | `内联` | `string` / 0..1 | 条件必填 | 仅当 `term_id` **不可解析** ∧ 该定义**可即时给出**（即 `内联` 行的取值本身即该定义）；两项皆真才准入，缺一即按 `降级行为` 处置 |
| `examples` | `用途` | `ExamplePurpose` / 1 | 必填 | `shape_anchor` / `satisfiability_witness` |

**并列 ≠ 择一**：同一父字段下的多个子标签**并存**（`产出物` 可同时有「形态」「判定口径」「语义判据」「判定边界」四维），与 `form` 式的**择一**形态不同——择一由父字段的 `form` 承载，并列由子标签承载。二者不可互相套用。

**「形态」一词的三个所指，按限定词区分**：① 无限定词时指 [§0.2](#02-子标签登记封闭集合) 登记的 `artifact` 子标签「形态」（产出物的书写格式描述）；② `scope.form` 的四个形态、③ `action.form` 的六个形态，分别写作 `scope.form` 与 `action.form`——它们**不是子标签**，不得写成 `- **形态**: boolean` 一类的子标签行（[§0.2](#02-子标签登记封闭集合) 未登记该子标签，写出来即非法）。

### 0.3 文档层定义的文本形态

条目的可省略字段有**文档层默认值**，其文本形态固定为下表，由文档自定一处，条目不复述。**本表即文档层定义项的唯一登记处**，故 [§0.1](#01-标签--字段对照) 不再列它们。首列的名称为定义项名；**该定义项所用的标签名写在"文本形态"列内**（属性行形态者即行内的 `**…**` 标记）。**本表各定义项的标签名与 [§0.1](#01-标签--字段对照) 的卡片字段标签、[§0.2](#02-子标签登记封闭集合) 的子标签名两两不同名**——复用一个别名会让同一行同时落进两张表，故此处不设"按位置分流"：解析器只按标签名归属，同名歧义在本机制下不存在。未登记的文档层定义项不合法；引用某个文档层定义项时，其取值来源即本表。

| 定义项 | 文本形态（含所用标签名） | 缺省语义 |
|---|---|---|
| 默认触发 | 属性行 `- **默认触发**: <事件>` | 触发即适用 |
| 默认模态 | 属性行 `- **默认模态**: <Modality>` | `must` |
| 模态词面对照表 | 三列表格：模态 / 词面 / 语义 | 无表，即 `should` 与 `may` 的**词面语义未锚定**，二者不可用 |
| 主体模式 | 属性行 `- **主体模式**: single` 或 `multi` | `single` |
| 默认主体 | 属性行 `- **默认主体**: <ActorRef>` | 单主体文档下的唯一主体 |
| 场景标签枚举 | 封闭枚举：场景标签名列表 | 无枚举，即 `scope.form = scenario_tag` 不可用 |

### 0.4 撰写通则

| 通则 | 内容 |
|---|---|
| 属性行格式 | 属性行格式 `- **<标签>**: <值>`；标签与冒号之间无空格，冒号后一个空格。**不匹配该格式的行不构成属性行**，按实际形态归入结构构件或注释（见下两条）；匹配而标签名未登记时**该行不合法**——解析器据 [§0.1](#01-标签--字段对照)／[§0.2](#02-子标签登记封闭集合)／[§0.3](#03-文档层定义的文本形态) 的封闭登记拒绝读取，撰写者不得写出 |
| 子标签 | 缩进 2 空格续行，格式 `- **<子标签>**: <值>`；子标签名须为 [§0.2](#02-子标签登记封闭集合) 的登记成员。**归属由子标签名唯一确定**（[§0.2](#02-子标签登记封闭集合) 的登记成员两两不同名），缩进只服务可读性、不承载归属信息 |
| 结构构件 | 除属性行与子标签行外，下列行不承载字段语义，统称**结构构件**：标题行、代码围栏及其围栏内文本、表格的表头行与分隔行、不匹配属性行格式的 `-` 列表项。结构构件参与解析（界定卡片与行序）但**不参与判定**。**①②③ 编号行不属此类**：它们是 `scope.form = boolean` 与 `action` 的 `ordered_steps`／`unordered_set` 形态的**内容载体**，随父字段参与判定。本术语是**载体层**的成员清单：换载体时随文本形态一并重述，其**机制层义务**是"除已登记的顶层字段行与子标签行外，一切构件不参与判定"——该义务不随载体改变 |
| 注释 | `#` 起至行尾**仅作说明，不参与判定**；不得承载唯一信息。**仅指属性行或子标签行之内的行尾说明**：行首 `#` 是 Markdown 标题标记、属结构构件，**不是注释**；代码围栏内的一切内容按结构构件处置，不剥离注释 |
| 省略 | 条件必填 / 选填项在触发条件不成立时**整行不出现**，不得留空标签、不得写占位符 |
| 分隔 | 一个字段内的多个维度**各占一行子标签**；**不得在字段值内自造分隔记号**（如「X：」「Y：」）来堆放并列维度。**本通则优先于行文层的一般列表要求**：卡片字段行内的并列项一律取子标签行（[§0.2](#02-子标签登记封闭集合)）或 ①②③ 编号行（`scope`／`action` 的形态专属写法），**不取 Markdown 列表项**——后者在卡片载体上属结构构件、不参与判定（本条与 `doc-writing` 的"三项及以上改用列表"不冲突：该要求适用于一般正文，卡片字段行由本通则专属规定） |
| 大小写 | **字段名与子标签名**一律 ASCII `snake_case`（[§0.1](#01-标签--字段对照) 的"字段"列、[§0.2](#02-子标签登记封闭集合) 的登记成员）；**枚举值**一律 ASCII 小写短码。本通则约束**本文的登记名与取值**，不约束卡片文本里的**文本标签**——后者写在 [§0.1](#01-标签--字段对照) 的"文本标签"列，可为中文 |
| 求值 | 文本逐行解析为键值对。**归属只按标签名**：标签名与 [§0.1](#01-标签--字段对照)／[§0.2](#02-子标签登记封闭集合)／[§0.3](#03-文档层定义的文本形态) 的登记成员一一对应。三处登记**两两不同名**（见 [§0.1](#01-标签--字段对照)、[§0.3](#03-文档层定义的文本形态)），故一名只归一表，**不依赖行文位置分流**；各处登记不得互串 |

### 0.5 判定真值源（越界即失效）

本表对判定者构成**封闭**约束：判定只许读本表"允许来源"列出的构件。**本表的完备性覆盖三类登记构件**——[§0.1](#01-标签--字段对照) 的顶层字段、[§0.2](#02-子标签登记封闭集合) 的子标签、[§0.3](#03-文档层定义的文本形态) 的文档层定义项：三类中的每一个都或落进某个判定输入行，或落进"不参与判定"行，**不留第三种去向**。完备性由本 skill 内的校验脚本机械校验（`scripts/verify.js`，随本 skill 分发；判据为**三类各自的成员集合与"允许来源"列的引用集合双向包含**）。**若某构件出现在任一登记表而未落入本表，该构件不参与判定**——这是本表的默认，且该默认会导致**静默误解**（撰写者以为它生效、判定者依本表不予读取），故按 [F-14](#f-14-failure_behavior--失败行为) 的择一判据归 `fail_loud`：由该校验脚本**拒绝**，而非靠人工比对发现。

**"允许来源"是判定输入可读构件的集合，不是构件的归属划分**：同一构件可同时被多个判定输入读取（如 `overrides` 既进"强度"又进"胜负"），判定输入的划分只回答"这个输入读什么"，不回答"这个构件只属于谁"。某一输入是否读某构件，最终以 [§2](#2-字段规则定义) 该字段自身条目为准。表中以 `名字` 引用的 [§0.3](#03-文档层定义的文本形态) 成员写的是**定义项名**（该表首列），不是卡片的文本标签。

| 判定输入 | 允许来源 |
|---|---|
| 生效条件 | `when`、`scope` 及其子标签（`连接`）、`actor`、`external_exceptions`、[§0.3](#03-文档层定义的文本形态) 的 `默认触发`、`主体模式`、`默认主体`、`场景标签枚举` |
| 强度 | `modality`、`overrides`、[§0.3](#03-文档层定义的文本形态) 的 `默认模态`、`模态词面对照表` |
| 行为 | `action` 及其子标签（`不变量`）、`failure_behavior` 及其 `行为` |
| 完成判据 | `artifact` 的 `判定口径`／`语义判据`、`examples` 及其 `用途` |
| 产出物形态 | `artifact` 的 `形态`（书写格式描述；**不判成立与否**，[§0.2](#02-子标签登记封闭集合) 登记了它这唯一职能） |
| 判定范围 | `artifact` 的 `判定边界`（界定边界；**不判成立与否**） |
| 胜负 | `overrides`、`coverage_point` **的存在性**（该构件在载体上出现即成立，取值不参与）、`覆盖内容`（外置覆盖内容的指针） |
| 引用完整性 | `id`、`overrides`、`external_exceptions`、`actor`、`scope` 的场景标签取值、`覆盖内容`、`dependencies` 及其子标签（`权威源`／`降级行为`／`内联`） |
| **不参与判定** | `title`、`layer`、`overridable`、`why`、一切结构构件与注释 |

归入依据不在本表复述：[§0.1](#01-标签--字段对照) 所登记字段的判定维度取自其自身的 [§2](#2-字段规则定义) 条目，逐字段的判定后果以该处为准。

**判定分两层，两层正交**：`判定口径` 给出可机械求值的部分，`语义判据` 给出无法机械求值的谓词。两者的处置不同——机械层由判定者逐项求值；语义层**不表示"可以跳过"**，判定者须给出判定与理由并单列，无法判定时显式列出交还使用者，**不得计入通过项**。机械层通过不赦免语义层不通过。`examples` 及其 `用途` 的判定后果取 [F-17](#f-17-examples--示例)，本条不另立层级。`判定边界` 不参与"是否成立"的判定，它界定判定的**范围**：边界内不成立即违规，边界外不由本条判定。

> 推论：写在注释、标题与层标签里的任何限制都是**装饰**，不具备约束力。要生效就必须落在上表允许的字段里——"落在表外"不是一种可选去向：它既不生效，也会被上述完备性校验拦下。

## 1. 规则卡片模板

条件不成立的行**整行删除**，不留空值。

```markdown
{{heading_level}} {{id}} {{title}}
- **模态**: {{modality}}      # modality；偏离默认 must 时才写
- **主体**: {{actor}}         # actor；多主体文档才需声明
- **when**: {{trigger_event}} # 触发事件；省略即"触发即适用"
- **scope**: {{scope}}        # 适用域；省略即全集
- **动作**: {{verb}} {{object}}
- **产出物**: {{artifact_name}}
  - **形态**: {{artifact_shape}}      # 必填
  - **判定口径**: {{rubric}}          # 可机械求值；与语义判据至少出现其一
  - **语义判据**: {{semantic}}        # 不可机械求值；须显式给出，不得默认通过
  - **判定边界**: {{boundary}}        # 本条判定不含的对象
- **外部例外**: {{ref_id}}     # 可重复；例外源不在本条内时
- **覆盖点**: {{point_id}}     # 本条可被他条覆盖时（隐含 overridable = true）
  - **覆盖内容**: {{content_ref}}  # 覆盖内容可外置时
- **覆盖**: {{rule_id}}        # 可重复；只写正向
- **层**: {{layer}}            # safety / policy / style；纯分类，选填
- **失败行为**: {{mode}}       # fail_safe / fail_loud
  - **行为**: {{behavior}}       # 本条有外部依赖时
- **依赖**: {{term_id}}@{{version}}
  - **权威源**: {{authority_source}}
  - **降级行为**: {{unresolved_behavior}}  # 须为 fail_loud
  - **内联**: {{inline_definition}}        # 仅当 term_id 不可解析 ∧ 该定义可即时给出
- **why:nb**: {{goal_criterion}}  # 仅适用集开放时
- **示例**: illustrative {{example}}  # 仅谓词无法闭合时
  - **用途**: {{purpose}}          # shape_anchor / satisfiability_witness
```

**并列维度的承载**：`产出物` 的四个子标签可**同时出现**，各自一行；`判定口径` 与 `语义判据` 至少出现其一（二者都出现时两层正交，机械层通过不赦免语义层）。判定与产出物的界面不得互串：`判定口径` 之外的维度不得塞进 `动作` 值内。

**标题行的级别**：`{{heading_level}}` **由文档自身的层级结构给定，不由条目自携**，且同一文档内全部条目的级别一致。级别是**该文档中承载条目的那一层标题**：条目直接承载于文档最上层时，取文档 H1 的下一级（H1 为 `#`，条目即 `##`）；条目承载于某个分组标题之下时，取其所在分组的下一级。缺省 `###`——即未作声明且文档存在分组标题时的取值。级别不写进任何属性行，读者从同一文档内既有的条目标题行即可读出。该级别对任何承载卡片的文档同等适用——级别只由该文档自身的层级结构决定，不由本文指定。

## 2. 字段规则定义

### F-01 `id` —— 规则标识

| 项 | 定义 |
|---|---|
| 文本标签 | 标题行首段：`{{heading_level}} {{id}} {{title}}`；级别由文档层级结构给定，全文档一致 |
| 类型 / 基数 | `RuleId` / 1 |
| 必填性 | **必填**（结构校验失败条件之一，缺失即不合法） |
| 取值约束 | 受控 ASCII 短码 + 前缀，形如 `R-014`；正则 `^[A-Z][A-Z0-9]{0,7}-[0-9]{2,4}$`；须正则化，逐字复制不产生形变；**在承载文档内唯一** |

**前缀**

`id` 的前缀由**承载本文档自己的条目**命名，形态为 `<前缀>-<编号>`。**前缀只承担文档内的分类职能**，不跨文档隔离：不同的文档各自维护自己的编号空间，两篇文档各自出现编号相同的一条规则**不构成冲突**——它们分处两篇文档，各自的引用在其文档内即可解析。

**前缀不设登记表**。前缀的占用可由条目标题行直接扫回（形如 `## C-01`），把占用另列一表即是同一事实的第二处表示，随条目标题增删而分叉；而"某前缀的语义域是什么"是自由文本，无可机械求值的判据，落成表格无法被任何判定读取。**故前缀不参与任何判定**：引用完整性只判形态与文档内唯一（[§3.4](#34-引用完整性)），不判前缀是否在某处登记。

本文 [§2](#2-字段规则定义) 内 `F-xx` 形式的编号是**字段定义的章节序号**，不是规则卡片 ID——它们不出现在条目标题行上，也不得被任何 `overrides[]`／`external_exceptions[]` 引用。规则卡片 ID 与字段定义章节号分属两个命名空间，不得互相代替。

**撰写规则**

1. 发布后**不得重用、不得改义**：即便原条被删除，该 ID 也不得分配给新语义。
2. 与正文语义无关：不得把语义压进 ID 试图承载信息。
3. 不得由 `title` 替代：`title` 不参与判定，也不得充当引用句柄。

**参与判定**：`id` 是引用完整性的锚点——`overrides[]`、`external_exceptions[]` 都指向它。`id` 自身不改变规则强度或适用范围。

### F-02 `title` —— 锚标题

| 项 | 定义 |
|---|---|
| 文本标签 | 标题行次段 |
| 类型 / 基数 | `string` / 0..1 |
| 必填性 | 选填 |
| 取值约束 | 无结构约束；服务于人类阅读与检索 |

**撰写规则**

1. **不参与判定**：标题与规则强度、适用范围、执行后果均无关。
2. **不得充当引用句柄**：需要被引用的对象必须是有 ID 的规则或命名谓词，不得用标题引用。
3. 允许在标题中做人类可读的概括，但概括与字段内容不一致时**以字段为准**。

### F-03 `modality` —— 模态

| 项 | 定义 |
|---|---|
| 文本标签 | `模态` |
| 类型 / 基数 | `Modality` / 0..1 |
| 必填性 | **条件必填**：取值偏离文档默认 `must` 时 |
| 取值约束 | 四值封闭枚举，见下表。缺失即按文档默认 `must` |

| 值 | 语义 |
|---|---|
| `must` | 未标注时的默认值 |
| `must_not` | 独立取值；**否定落在模态位而非动作位** |
| `should` | 词面语义由**文档层封闭对照表**锚定 |
| `may` | 词面语义由**文档层封闭对照表**锚定 |

**撰写规则**

1. 模态是**唯一真值源**，由条级自携；文档层只提供默认值与词面对照表，不得在条级另立语义词表。
2. `must_not` 的动作**不得点名被禁对象的字面**，须改写为**类别级**或**正面等价**表述。
3. 安全关键项须配生成后过滤——该过滤由执行环境层承载，**不是本结构的字段**。
4. 模态枚举自始为**四值**（见上表四行），**不存在**表外的第三值（如绝对数值强度），只能在四值内取值。

### F-04 `actor` —— 执行主体

| 项 | 定义 |
|---|---|
| 文本标签 | `主体` |
| 类型 / 基数 | `ActorRef` / 0..1 |
| 必填性 | **条件必填**：文档为多主体 |
| 取值约束 | 执行主体标识，**必须可由文档层解析**；单主体文档缺省取文档默认（[§0.3](#03-文档层定义的文本形态) 的 `主体模式` 未声明时取 `single`） |

**撰写规则**

1. 声明本条**对谁生效**；主体不同则规则不适用，而非强度变化。
2. 引用完整性：解析不到的主体标识不得写入，须先在文档层登记。
3. 单主体文档下省略本行，不写"全体"之类的兜底词。

### F-05 `when` —— 触发事件

| 项 | 定义 |
|---|---|
| 文本标签 | `when` |
| 类型 / 基数 | `TriggerEvent` / 0..1 |
| 必填性 | **条件必填**（适用性槽组之一） |
| 取值约束 | 可观测事件：在**时刻上"发生"**。缺失即"规则触发即适用" |

**撰写规则**

1. **不得写状态**。状态（"处于…中"、"已启用"）属于 `scope`，此处只接受事件。
2. 判据须可观测：能被外部判定者观察到"发生了"，而非需要推断。
3. 执行时序**不属于本字段**，也不属于适用性槽——时序归 `action` 槽（如 `ordered_steps`）。
4. 与 `scope` 的分工：`when` 管"何时启动"，`scope` 管"在什么域与前置状态下适用"；二者构成适用性槽组，缺省语义不同（`when` 缺省 = 触发即适用，`scope` 缺省 = 全集）。

### F-06 `scope` —— 适用域与前置状态

| 项 | 定义 |
|---|---|
| 文本标签 | `scope` |
| 类型 / 基数 | `Scope` / 0..1 |
| 必填性 | **条件必填**（适用性槽组之一） |
| 取值约束 | 适用域与前置状态：在区间内**成立**、**可判定**。缺失即全集。形态四选一，不并存 |

| `form` | 含义 | 文本写法 |
|---|---|---|
| `universe` | 无标记全集 | 省略本行（该形态即 `scope` 整行不出现，形状为空，无可照抄之物） |
| `atomic` | 单一原子谓词 | `- **scope**: {{谓词}}` |
| `boolean` | 合取/析取组合 | ≤3 合取可分行编号；>3 或含 `or` 必须给连接词行 |
| `scenario_tag` | 全局定义的场景标签 | `- **scope**: {{场景标签名}}`（标签本体在文档层封闭枚举定义） |

**撰写规则**

1. 谓词须**可判定**：取自全局封闭枚举字段，或为自然语言但可机械判定的事实。**后者不设、也不可能有全局合法集合**——若存在这样的集合，该谓词即归 `scenario_tag`，`atomic` 这一形态便无存在理由。故"是否可机械判定"由判定者按**语义判据**处置（[§0.5](#05-判定真值源越界即失效)）：显式给出判定与理由并单列，无法判定时交还使用者，不计入通过项。
2. **例外一律改写为 `scope ∧ ¬P`**，由原子谓词取反承担。**不设 `except` 字段**：
   - 本地可判定的例外写在 `scope` 内，**不得**写成外部例外。
   - 例：`- **scope**: 变更涉及生产环境配置  # ¬P（非生产环境）即不适用`
3. 「连接」是**显式结构标记**，承载在 [§0.2](#02-子标签登记封闭集合) 登记的子标签行上——**不写 `operators` 这类未登记字段名**：字段名与子标签名只能取 [§0.1](#01-标签--字段对照) 与 [§0.2](#02-子标签登记封闭集合) 的登记成员（[§0.4](#04-撰写通则)「求值」）。`>3` 项或含 `or` 时**必须**给出。写法：`- **连接**: (① and ②) or ③`。**连接词个数恒等于编号合取项个数减一**（如 `(① and ②) or ③` 以两个连接词串起三个编号项）；连接词的合法记号与优先级见 [§0.2](#02-子标签登记封闭集合) 的「连接」行。
4. `form = universe` 的"无标记全集"即 `scope` 整行不出现，取该字段的缺省语义；**该形态不带任何职能含义**——"某条规则承担兜底职能"是册层的事，不由本字段承载，也不在字段层另设区分记号。

**子结构写法**

```markdown
# boolean，≤3 合取
- **scope**: 同时满足全部三项：
  - ① 变更涉及生产环境配置
  - ② 变更已通过代码评审
  - ③ 变更窗口在维护期内

# boolean，>3 或含 or，必须给「连接」
- **scope**: 显式布尔组合
  - ① 变更涉及生产环境配置
  - ② 变更已通过代码评审
  - ③ 触发人为发布工程师
  - **连接**: (① and ②) or ③
```

**禁止形态**

- 以自然语言"或" / "和/或"表达析取（须用带「连接」的 `boolean`）。
- 以触发词 / 关键词表表达谓词（那既非事件也非可判定事实）。
- 嵌套否定。
- 把执行时序写进本槽。

### F-07 `action` —— 动作

| 项 | 定义 |
|---|---|
| 文本标签 | `动作` |
| 类型 / 基数 | `Action` / 1 |
| 必填性 | **必填** |
| 取值约束 | 形态六选一，**非当前形态的字段不得出现**；抽象度固定在"**工具无关的具体动作级**" |

| `form` | 含义 | 文本写法 |
|---|---|---|
| `imperative_core` | 祈使核 `verb` + `object` | `- **动作**: {{verb}} {{object}}`（合并为一句） |
| `predicate_constraint` | 可判定谓词 | `- **动作**: {{predicate}}`（本行**只承载谓词**；该谓词如何求值归 `artifact` 的判定维度，见 [§0.5](#05-判定真值源越界即失效)） |
| `pre_post_assertion` | 完成后必须成立什么 | `- **动作**: 完成后成立 — …`（本行承载**后置条件本身**；该条件是否成立的判据归 `artifact`） |
| `goal_state_invariant` | 终态谓词 + 不变量 | `- **动作**: 目标状态 — …`，另起 2 空格缩进的子行 `- **不变量**: …` |
| `ordered_steps` | 有序步骤：以数据依赖定序的编号行，**单步不成立该形态** | ①②③ 编号行；**仅当动作间有数据依赖**时使用 |
| `unordered_set` | 无序动作集合：并列的编号行，**单步不成立该形态** | ①②③ 编号行 + 显式声明次序无关 |

`ImperativeCore` = `{ verb: string (必填), object: string (必填) }`。

**模板完备的形态**：上表中 `imperative_core`、`predicate_constraint`、`pre_post_assertion` 三者的形状由本表**逐字给出**（单行，前缀与占位符均已写明），撰写者替换占位符即得，**没有可自行发明的余地**。故本文不为它们另附字面样例——样例在此不增加信息（[F-17](#f-17-examples--示例) 的触发条件「谓词无法闭合」不成立），也不得据以自行改变其形状。需要样例的仅是形状无法从本表直接读出的多行形态（`goal_state_invariant`、`ordered_steps`、`unordered_set`），样例见本节末。

**撰写规则**

1. 产出物**不写在动作里**，由顶层 `artifact` 承载。`action.form = imperative_core` 时动作核只留 `verb` + `object`。
2. **`ordered_steps` 的准入条件只有一条：步间存在数据依赖。** 仅"看起来有先后"不构成理由；无数据依赖就应写成 `unordered_set` 或并列子句。
3. `unordered_set` 必须显式声明"次序无关"，该声明写在 `action` 值内，是该形态的必要组成。
4. 判定与格式输出解耦：**行为写在 `action`，完成判据写在 `artifact` 的子标签，格式依据写在 `artifact` 的「形态」**。三者的分工是——`action` 回答"要做什么"，`artifact.判定口径`／`语义判据` 回答"凭什么算完成"，`artifact.形态` 回答"完成时长什么样"。判定依据**不得**写在 `action` 值内：那会使同一语义在 `action` 与 `artifact` 两处承载，[§0.5](#05-判定真值源越界即失效) 的完成判据真值源随之失效。

**禁止形态**

| 禁止 | 理由 / 合法替代 |
|---|---|
| 意图级表述（"确保一致性"、"消除歧义"） | 不可观测；须落到具体动作 |
| 纯目标状态且动作槽为空 | 缺必填；`goal_state_invariant` 也须给出终态谓词 |
| 程度副词（"尽量"、"适当"） | 不可判定 |
| 工具 / API / 参数级细节 | 抽象度越界，须停在工具无关层 |

```markdown
# ordered_steps：仅当动作间有数据依赖
- **动作**: 按序执行（步间有数据依赖）
  - ① 导出当前生产配置快照
  - ② 以快照为输入逐项比对安全基线清单
  - ③ 以比对结果为输入生成驳回项列表

# unordered_set：显式声明次序无关
- **动作**: 以下动作次序无关
  - ① 校验变更元数据完整性
  - ② 校验变更影响面声明

# goal_state_invariant
- **动作**: 目标状态 — 全部变更项均已判定为通过或驳回
  - **不变量**: 判定过程中不得修改原始变更内容
```

### F-08 `artifact` —— 可观测产出物

| 项 | 定义 |
|---|---|
| 文本标签 | `产出物`（顶层行承载产出物名称） |
| 类型 / 基数 | `Artifact` / 1 |
| 必填性 | **必填** |
| 取值约束 | 完成后**可观测什么**；名称写在顶层行，格式与判据写在四个子标签行。**不并入 `action` 值**——`action` 承载行为，本字段承载完成判据（[§0.5](#05-判定真值源越界即失效)） |

产出物是**多维槽位**：名称在顶层行，以下四个子标签 `形态`／`判定口径`／`语义判据`／`判定边界` **并列承载**，各占一行。四者的基数、必填性与取值约束由 [§0.2](#02-子标签登记封闭集合) 统一登记，本节不复制。

**撰写规则**

1. 产出物是"完成"的唯一判据载体：写完 `action` 必须回答"完成时外部能看到什么"。
2. **两个判定维度不得互相替代，也不得混写在同一行**：机械可求值的写 `判定口径`，不可求值的写 `语义判据`。**在 `产出物` 值内自造分隔记号**（如「机械：」「语义：」）堆放两个维度，即违反 [§0.4](#04-撰写通则) 的分隔通则——那是子标签缺位时的补丁，不是合法写法。
3. **`语义判据` 不是免检项**：它无法机械求值，但必须显式给出；判定者须作出判定并写明理由，在结论中单列，无法判定时交还使用者。**把 `语义判据` 略去不计，等于宣称一个无法核实的条目已通过。**
4. **`判定边界` 是把"不判定"从判据里拆出来的归宿**：写明本条不判定的对象及其承担者，读者据此知道该由哪条判定，而不是从判据正文里读出一句"本条不判定…"。边界外的违规不由本条负责，但**边界内不得留白**。
5. 格式依据写在本字段的「形态」子标签，**完成判据写在本字段的「判定口径」／「语义判据」子标签**；行为写在 `action`。不得把格式要求塞进 `artifact` 子标签之外的地方，也不得把判定依据塞进 `action` 的格式描述里。

### F-09 `external_exceptions` —— 外部例外

| 项 | 定义 |
|---|---|
| 文本标签 | `外部例外`（可重复，每项一行） |
| 类型 / 基数 | `StrongRef[]` / 0..* |
| 必填性 | **条件必填**：例外源不在本条内 |
| 取值约束 | 命名谓词 ID 或规则 ID 的**强引用**；固定命名空间前缀；**禁自然语言** |

**撰写规则**

1. **本地可判定的例外不得写在此处**——它们属于 `scope` 的 ¬P。
2. 引用必须解析到规则 ID 或命名谓词 ID；不可解析时按本条 `failure_behavior` 处理。
3. 逐项一行，不合并、不写说明文字。

### F-10 `overridable` —— 可覆盖性

| 项 | 定义 |
|---|---|
| 文本标签 | **不单独成行**，由"覆盖点"行的存在性隐含 |
| 类型 / 基数 | `boolean` / 0..1 |
| 必填性 | **条件必填**：本条可被他条覆盖 |
| 取值约束 | 为 `true` 时 `coverage_point` 变为**必填** |

**撰写规则**

1. `overridable` 可由 `coverage_point` 的存在性推导，故**不写行**。
2. 写"覆盖点"行即等价于声明 `overridable = true`；不写即未被覆盖。

### F-11 `coverage_point` —— 覆盖点

| 项 | 定义 |
|---|---|
| 文本标签 | `覆盖点` |
| 类型 / 基数 | `CoveragePoint` / 0..1 |
| 必填性 | **条件必填**：`overridable = true`（即写出本行） |
| 取值约束 | 顶层行值为覆盖点标识，必填；子标签 `覆盖内容` 的基数、必填性与取值约束由 [§0.2](#02-子标签登记封闭集合) 登记 |

**撰写规则**

1. **被覆盖方必须内嵌自身可被覆盖的事实**——即本条内必须出现"覆盖点"行。覆盖关系不能只从对方单边可见：参与判定的是**该行的存在性**（[F-10](#f-10-overridable--可覆盖性) 由它推导 `overridable = true`），不是它的取值。
2. 覆盖内容可外置为强引用，以避免条件在多处复制后漂移。
3. **顶层行值不参与判定**：覆盖关系由覆盖方的 `overrides` 指向被覆盖方的**规则 ID**（[F-12](#f-12-overrides--正向覆盖指针)），没有任何判定读覆盖点标识的取值。该值仅为人类可读的标签，**不受命名或构造规则约束**，同册内重名或留空均不影响判定；不得以它代替规则 ID 作引用句柄（[F-02](#f-02-title--锚标题) 的同类禁令）。

### F-12 `overrides` —— 正向覆盖指针

| 项 | 定义 |
|---|---|
| 文本标签 | `覆盖`（可重复） |
| 类型 / 基数 | `RuleId[]` / 0..* |
| 必填性 | **条件必填**：存在定向冲突 |
| 取值约束 | **只写正向指针**，列出被本条压制的规则 ID；去重；**不得自指** |

**撰写规则**

1. **只写正向**：本条写"我压制谁"，被压制方不写"我被谁压制"。
2. 目标必须是**已存在**的规则 ID；不得自指；同一 ID 不得重复出现。
3. 值只写规则 ID，**不得重复标签语义**（不要写 `overrides R-021`，只写 `R-021`）。
4. 绝对数值优先级（`priority`）不存在；强度由条级 `modality` + `overrides` 决定，无其它来源。

### F-13 `layer` —— 层标签

| 项 | 定义 |
|---|---|
| 文本标签 | `层` |
| 类型 / 基数 | `Layer` / 0..1 |
| 必填性 | **选填**：纯分类标签，需要标注规则主题时写 |
| 取值约束 | 封闭小集合：`safety` / `policy` / `style`。**不参与判定** |

**撰写规则**

1. 本字段是**纯分类标签，不参与判定**：写 `safety` 不会让规则更强，强弱只能由 `modality` 与 `overrides` 产生。
2. 随时可写，与本文档是否存在分层无关；层**不是**优先级的载体，本文不设据层裁决强弱的分层序表。优先级一律用 `modality` + `overrides` 表达。
3. 取值限 `safety` / `policy` / `style` 三值。**该集合的封闭性只服务于跨文档可比的分类，不承载判定**——故其扩展无须准入机制，取值集合的增减不影响任何规则的成立或强弱。

### F-14 `failure_behavior` —— 失败行为

| 项 | 定义 |
|---|---|
| 文本标签 | `失败行为`（顶层行值为 `模式`） |
| 类型 / 基数 | `FailureBehavior` / 0..1 |
| 必填性 | **条件必填**：本条有外部依赖 |
| 取值约束 | 顶层行值即 `模式`，必填，取 `fail_safe` 或 `fail_loud`；子标签 `行为` 的基数、必填性与含义由 [§0.2](#02-子标签登记封闭集合) 登记 |

| `模式` 取值 | 含义 |
|---|---|
| `fail_safe` | 默认填充 |
| `fail_loud` | 拒绝执行 |

**择一判据（按失败方向）**

- 存在**消费方可察觉的**安全默认 → `fail_safe`。
- 默认会导致**静默误解** → `fail_loud`。

判据锚在**默认值出错时消费者能否察觉**，不锚在消费者的实现品类：把"可察觉"写成某个具体模型或工具能识别，会使本判据随该工具的换代而失效。

**撰写规则**

1. `行为` 必填，须写出具体行为，不得写"报错"这类空泛表述。
2. **有外部依赖就必须写本行**：`external_exceptions` 不可解析、`dependencies` 不可解析时的降级行为都回落到这里。

### F-15 `dependencies` —— 依赖指针

| 项 | 定义 |
|---|---|
| 文本标签 | `依赖`（顶层行值为 `{{term_id}}@{{version}}`，可重复） |
| 类型 / 基数 | `Dependency[]` / 0..* |
| 必填性 | **条件必填**：含外部术语 |
| 取值约束 | 术语 ID + 版本在顶层行；三个子标签 `权威源`／`降级行为`／`内联` 的基数、必填性与取值约束由 [§0.2](#02-子标签登记封闭集合) 统一登记 |

**撰写规则**

1. **判定顺序**（与 [§0.2](#02-子标签登记封闭集合) 的 `内联` 准入同调）：可解析 → 写指针；`term_id` 不可解析 ∧ 该定义可即时给出 → 写 `内联`；其余不可解析情形 → 按 `降级行为` 处置。
2. 规则不承载知识本体；"自包含"指**可判定地解析**，非字面自足。
3. 禁止在条级写术语本体定义（`内联` 是唯一例外，且受"`term_id` 不可解析 ∧ 该定义可即时给出"两项条件限制）。
4. **`version` 不参与可解析性判定**：判"能否解析"只看 `term_id`（[§3.4](#34-引用完整性) 同此口径）。`version` 的用途是**解析成功后核对**——比对取回物是否即写作时所指的那一版。核对**只判相等**，不判新旧、不支持范围语义：二者不同即按 `降级行为` 处理，不猜测、不自动升级。该核对使"取回物静默换代"不致被当作解析成功。

**子结构写法**：`- **依赖**: {{term_id}}@{{version}}`；权威源、降级行为与内联定义各起一行 `- **权威源**: …`、`- **降级行为**: …`、`- **内联**: …`。

### F-16 `why` —— 理由 / 意图

| 项 | 定义 |
|---|---|
| 文本标签 | `why:nb`（`nb` = non-normative） |
| 类型 / 基数 | `WhyBlock` / 0..1 |
| 必填性 | 选填，**仅当适用集开放**。**开放性按行文记号判定**：`scope` 值内含"等 / 类似 / 视情况 / 合理"一类开放记号时视为开放，可写本行；不含则视为闭合，**不得写本行**。该**记号口径即本行的完整判据**：含记号即可写，不含即不得写，不另行追问"适用集是否真的开放"——那是无法机械求值的语义问题，若据它裁决，本触发条件便依赖读者推断了 |
| 取值约束 | 非规范标记块，须与规范段**物理分离** |

| 子标签 | 基数 | 必填性 | 约束 |
|---|---|---|---|
| （顶层行值） | 1 | 必填 | 理由内容；写成**目标状态 / 验收判据**，不写动机叙事；**禁道义词**（必须 / 不得 / should） |

**撰写规则**

1. 写成"目标是使…成立"一类的**验收判据**，不写"因为历史原因…"一类叙事。
2. **禁道义词**：出现"必须 / 不得 / should"即越界，那些属于规范段。
3. 外推须有本体谓词支撑，**冲突时本体优先**。
4. 适用集按上述记号口径判为闭合时**不写本行**——那时 `scope` 已经说清边界，理由块只会引入不可判定的口径。**不得以"语义上属于某一类"为由绕过记号口径**：`scope` 写成闭合原子谓词而 `why:nb` 声称适用集开放，即本条要禁止的写法。二者的冲突落在**卡片结构合法性**上——由 [§0.1](#01-标签--字段对照)／[§0.2](#02-子标签登记封闭集合) 的封闭登记与 [§3](#3-结构约束汇总) 的结构约束拦下，不进入判定者的判定输入（`why` 不参与判定，见 [§0.5](#05-判定真值源越界即失效)）。

### F-17 `examples` —— 示例

| 项 | 定义 |
|---|---|
| 文本标签 | `示例`（可重复；行首必须带 `illustrative`） |
| 类型 / 基数 | `Example[]` / 0..* |
| 必填性 | 选填，**仅当谓词无法闭合**：阈值方向歧义 |
| 取值约束 | 顶层行值为示例内容，必填，**须当规格而非说明对待**，行首固定常量 `illustrative`（**非 exhaustive**）；子标签 `用途` 的基数、必填性与取值由 [§0.2](#02-子标签登记封闭集合) 登记 |

**撰写规则**

1. **反例一旦揭示新边界，应改写 `scope` 谓词，而非保留示例**（谓词优先）。
2. 示例是规格而非说明：读者按示例办事时，示例的效力与谓词同级。
3. 多条示例每项一行，行首均标 `illustrative`；`用途` 为**必填**子标签，须与示例同行组内给出。
4. **`用途` 两个取值各有判定后果，不得混用**：`shape_anchor` 锚定产出物的书写形状，效力同 `artifact` 的「形态」——**不判成立与否**；`satisfiability_witness` 见证谓词可满足——参与完成判据，其成立以该示例满足谓词为准。示例与 `判定口径`／`语义判据` 冲突时以判据为准（示例是规格，判据是规格的判据），该冲突应在撰写期改写示例或 `scope`，不留到判定期仲裁。

**禁止**

- 未标 `illustrative` 的示例；`exhaustive` 标记。
- 输出侧自检型示例。
- 每条规则标配示例。
- 无差别预置全量边界反例。

```markdown
- **示例**: illustrative 跨环境同步时须附带源环境标识
  - **用途**: shape_anchor
- **示例**: illustrative 批量变更须附带批次编号
  - **用途**: satisfiability_witness
```

## 3. 结构约束汇总

### 3.1 触发条件总表

| 字段 / 子标签 | 触发条件 |
|---|---|
| `when` | 规则不是"触发即适用"时；不写即取该缺省（[F-05](#f-05-when--触发事件)） |
| `scope` | 规则的适用域不是全集时；不写即取该缺省（[F-06](#f-06-scope--适用域与前置状态)） |
| `modality` | 取值偏离文档默认 `must` |
| `actor` | 文档为多主体 |
| `external_exceptions` | 例外源不在本条内 |
| `overridable` + `coverage_point` | 本条可被他条覆盖 |
| `coverage_point.覆盖内容` | 覆盖内容外置为强引用 |
| `overrides` | 存在定向冲突 |
| `layer` | 需要标注规则主题时（纯分类，不影响判定） |
| `failure_behavior` | 本条有外部依赖 |
| `failure_behavior.行为` | 写出 `failure_behavior` 即必填 |
| `dependencies` | 含外部术语 |
| `dependencies.权威源` / `降级行为` | 写出 `dependencies` 即必填 |
| `dependencies.内联` | `term_id` 不可解析 ∧ 该定义可即时给出 |
| `why` | 适用集开放，按行文记号判定：`scope` 值内含"等 / 类似 / 视情况 / 合理"（[F-16](#f-16-why--理由--意图)）；不含记号即闭合，不得写本行 |
| `examples` | 谓词无法闭合（阈值方向歧义） |
| `examples.用途` | 写出 `examples` 即必填 |
| `artifact.判定口径` | 存在可机械求值的判据；与 `语义判据` 至少出现其一 |
| `artifact.语义判据` | 存在不可机械求值的谓词；与 `判定口径` 至少出现其一 |
| `artifact.判定边界` | 本条不判定的对象须交给其他承担者 |
| `scope.连接`（`form = boolean`） | `>3` 合取或含 `or` |
| `action.不变量`（`form = goal_state_invariant`） | 该形态下须给出不变量 |

### 3.2 互斥与择一

| 约束 | 内容 |
|---|---|
| `scope.form` | 四形态**不并存**于同一槽位，`form` 决定该形态专属字段的必填性 |
| `action.form` | 六形态**择一**，非当前形态的字段不得出现 |
| 子标签并列 | 同一父字段下的子标签**并存**（如 `产出物` 的四个子标签）；择一由 `form` 承载，不由子标签承载 |
| 本地例外 | **不设独立字段**（无 `except`）；由 `scope` 的 ¬P 吸收 |
| 覆盖方向 | 只写 `overrides`；**禁止反向指针** |

### 3.3 计数上限

| 约束 | 量级 | 性质 |
|---|---|---|
| 任一条规则在任一执行场景下**同时激活的约束数** | ≤ 5–6 | 经验量级，超出即结构性风险 |
| 同一条内并列的同构子句数 | ≤ 5–7，超出**拆条而非压缩** | 经验量级 |
| `scope` 的编号合取项 | ≤ 3 纯合取可分行编号；>3 或含 `or` 必须给「连接」子标签 | 硬约束 |
| 必填核心 | 见 [§0.1](#01-标签--字段对照) 字段表中标为"必填"的三行（`id`、`action`、`artifact`）；适用性槽组不含在内 | 硬约束 |

> 同时激活约束数 = 该条已出现的**顶层字段数** + 已出现的**子标签数**，两部分各扣去下列**豁免项**（封闭集合，仅此两项）：顶层豁免 `id`、`title`（[§0.1](#01-标签--字段对照) 中标为"标题行首段／次段"者，不单独成字段行）；子标签豁免 `形态`（[§0.2](#02-子标签登记封闭集合) 中唯一承担产出物书写格式描述的子标签）。**"描述性必填子标签"不是可自行判断的一类**——本注只认 `形态` 这一项，其余子标签一律计入。据此，`产出物` 四维写全时占三席（`判定口径`、`语义判据`、`判定边界`），`形态` 占零席。

**两类性质的行如何处置**（本表"性质"列的判定后果）：

- **硬约束**：超过即**不合法**，判定者出具不通过。
- **经验量级**：**不参与"成立与否"的判定**——它是给撰写者的结构性风险信号。超过时判定者在结论中**提示**该风险并点名超限项，但**不因此否决该条**。理由：它度量的是认知负担，而认知负担随规则内容变化——同一条数在纯 `imperative_core` 的简单规则上毫无负担，在含 `goal_state_invariant` 的复杂规则上却可能已难判。故阈值为经验值，**不得**据它出具不通过，**也不得**要求把它精确化为单一常数：任何定值都同样不度量认知负担，反而会把风险信号误升为硬约束。
- 本表两列的口径由此闭合：**计数**可机械求值（照上式复算），**阈值**只作提示。二者合起来即是本表的完整判据，**不存在待精确化的剩余项**。

### 3.4 引用完整性

| 引用 | 要求 |
|---|---|
| 规则 ID（任何位置） | 形态须匹配 `^[A-Z][A-Z0-9]{0,7}-[0-9]{2,4}$`，且在**承载文档内**唯一解析到一条规则；形态不符或在该文档内解析到多条即不可解析。**引用不判前缀的含义**——前缀不设登记，跨文档的同名 ID 不在此列，本文档的引用只在本文档内解析 |
| `overrides[]` | 目标必须是已存在规则 ID；不得自指；去重 |
| `external_exceptions[]` | 必须解析到规则 ID 或命名谓词 ID；不可解析 → 按 `failure_behavior` 处理 |
| `dependencies[].term_id` | 必须可由文档层或执行环境层解析；不可解析 → 执行「降级行为」子标签的取值。**可解析性只由 `term_id` 判定**，行内的 `{{version}}` 不参与该判定；`version` 仅用于解析后核对（[F-15](#f-15-dependencies--依赖指针) 规则 4） |
| `scope.scenario_tag` | 必须是文档层封闭枚举成员 |
| `actor` | 必须可由文档层解析 |

## 4. 禁止字段与禁止形态

| 禁止项 | 合法替代 |
|---|---|
| `except`（本地例外字段） | `scope` 的 ¬P（原子谓词取反） |
| `overridden_by`（反向指针） | 仅写 `overrides` |

| 未标 `illustrative` 的示例、`exhaustive` 标记 | 行首固定常量 `illustrative` |

| 触发词 / 关键词表 | `scope` 的可判定谓词 |
| 适用性槽中的执行时序 | `action` 槽 |
| 自然语言析取（"或" / "和/或"） | `scope` 谓词（`atomic` 或带 `连接` 的 `boolean`） |
| 嵌套否定 | 原子谓词取反 |
| 自检 / 输出侧判定字段 | 外部判定者 |
| 条级模态语义词表 | 文档层封闭对照表 |
| 绝对数值强度的第三值 | 四值枚举内的取值 |
| **字段值内的自造分隔记号**（「X：」式并列维度） | [§0.2](#02-子标签登记封闭集合) 的具名子标签 |
| **未在 [§0.2](#02-子标签登记封闭集合) 登记的子标签名** | 登记后使用；或改用已登记子标签 |

| **把"本条不判定 X"写进判据正文** | `判定边界` 子标签，写明承担者 |

## 附. 规范化完整示例

（与 [§1 模板](#1-规则卡片模板) 同形）

三张卡片互为参照，故示例内出现的每个规则 ID 引用都能在示例内解析（[§3.4](#34-引用完整性)）。

```markdown
### R-009 安全基线条款的正确性由基线仓库承担
- **scope**: 安全基线清单的任何条款
- **动作**: 维护基线条款的正确性并随生产环境变化更新
- **产出物**: 基线清单版本
  - **形态**: 版本号加条款清单
  - **判定口径**: 每条条款都有一个稳定条款 ID，且同一 ID 在全清单内只出现一次
- **失败行为**: fail_loud
  - **行为**: 无法取得基线仓库时中止并上报，不沿用上一次的缓存副本

### R-021 变更须先经安全基线核对
- **when**: 收到变更实施请求
- **scope**: 变更涉及生产环境配置  # ¬P（非生产环境）即不适用
- **动作**: 在实施前逐项核对变更与安全基线清单
- **产出物**: 核对记录
  - **形态**: 逐条记录，每项含 {变更ID, 基线条款ID, 结论}
  - **判定口径**: 每条变更都有对应的核对结论，且结论取值限于通过与驳回
- **覆盖点**: production_change_review  # 声明本条可被 R-014 覆盖

### R-014 审查并驳回不合规变更
- **主体**: 审查者            # 多主体文档才需声明
- **when**: 收到变更审查请求
- **scope**: 变更涉及生产环境配置  # ¬P（非生产环境）即不适用
- **动作**: 逐项核对变更与安全基线清单
- **产出物**: rejections[]
  - **形态**: 数组，每项含 {变更ID, 违反的基线条款, 证据}
  - **判定口径**: 每项的三个字段均非空，且变更ID 存在于本次变更清单
  - **语义判据**: 证据是否足以支撑"违反"的结论
  - **判定边界**: 基线清单本身的正确性不由本条判定，见 R-009
- **失败行为**: fail_loud
  - **行为**: 基线清单未解析时中止并上报，不猜测条款
- **依赖**: BASELINE-SPEC@v3
  - **权威源**: 安全基线清单仓库
  - **降级行为**: 未解析时中止并上报
- **覆盖**: R-021
```

**本示例与 [§3.3](#33-计数上限) 量级的关系**：本示例为示范**多条条件必填字段**而承载了 `主体`、`判定边界`、`覆盖`、`依赖` 与 `失败行为`，其「同时激活约束数」按 [§3.3](#33-计数上限) 的口径计已越出该量级——**逐卡计数由读者按该口径从卡片本身复算**，本处不转述。5–6 是结构性风险信号而非硬约束（[§3.3](#33-计数上限) 已如此定性），故本示例保留完整形态；实际撰写时按 [§3.3](#33-计数上限) 拆条，不应以本示例的计数为常态。**本示例不出现 `why:nb`**：三张卡片的 `scope` 均为闭合原子谓词，按 [F-16](#f-16-why--理由--意图) 规则 4 不得写该行。
