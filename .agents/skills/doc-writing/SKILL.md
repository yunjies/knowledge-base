# 文档行文撰写工序

本 skill 的工序由一条约束链推出：判定只读各条随文写出的字段，故凡要生效的语义都必须落在这些字段里，写在标题、注释或结构标记中的限制不具约束力。写作者能检查的对象只有自己写下的每一处表述，故工序按表述的生命周期排列：先判该不该写，再定怎么写，最后判能不能删。执行时自上而下走。

## 判据源与范围

本 skill 的按条判据以[文档撰写规范](reference/doc-writing-constraints.md)（下称规范册）为唯一判据源，本 skill 不复制其条款。工序只编排落笔次序，不新增判据；规范册未覆盖的情形不得自行发明判据，须显式报出该情形与其归属。本 skill 工序中的 `D-nn` 即规范册的条目编号。

本 skill 管文档正文的行文表述，不论文档的领域与体裁；某一步是否适用于当前文档，取该步所引条目自身写出的适用条件。规则卡片与规范册的字段结构、流程类文档的图与节点结构不归本 skill，取[规则卡片与规范册撰写工序](../rule-card-writing/SKILL.md)与[流程类文档撰写工序](../process-doc-writing/SKILL.md)。

## 工序

1. **判可写性**：对拟写入的每处事实先过三道关——它是否是读者能从原始信息自行取回的事实（`D-02`）；它是否借另一份记录的条目定位（`D-03`）；它是否是命令、配置、默认值一类操作事实（`D-19`）。三者各自给出取回路径、直接成句、实际运行三种改写方向。
2. **定层级**：按该事实的适用范围与读者群选承载文档（`D-20`）；局部约定不上升，全局内容不散落。
3. **核术语**：对抽象术语先核对是否存在更确切的技术对象名（`D-13`）；命中确切对象即改用它。
4. **写成命题**：每处表述参照系取文档自身——
   - 陈述当前状态而非变更史（`D-04`）。
   - 不采纳仅该次会话可解析的坐标（`D-05`）。
   - 只保留读者无法从对象本身重建的契约（`D-06`）。
5. **补归属**：未决事项写成含承担者与动作的标记，估计值写成含来源标记的观测值或可判定的失败边界（`D-07`）。
6. **统一词面**：全文行文语言一致（`D-08`）；同一概念只用一个术语（`D-17`）。
7. **造句**：逐项落笔——
   - 指令点明执行主体与动作（`D-15`）。
   - 一句只承载一条指令或一组紧密条件，并列达三项及以上改用列表（`D-16`）。
   - 指路性引用一律写成 Markdown 链接（`D-01`）。
   - 每个段落写成不换行的单个物理行（`D-21`）。
   - 全部结构一律用 Markdown 原生语法承载，正文内不出现 HTML 标签（`D-25`）；`<b>`／`<strong>` 改 `**…**`，`<br>` 改空行分段，`<table>` 改管道表格，`<div>` 一类容器改列表或取消包裹。
8. **判承重**：逐句追问该句被谁依赖、依赖哪一类，以保住承重约定为下限、以删除推理叙述与重复装饰为上限（`D-10`）；会脱离上下文单独展示的片段须自足（`D-12`）。
9. **述用途**：面向使用者陈述某对象用途时，落在读者能用它做什么、何时选用与主要代价，不叙述其内部角色、注册项或组件构成（`D-18`）。
10. **按体裁补必备项**：先认体裁，再补该体裁的必备项——
   - 指令类文档须写明行为护栏与显式范围限制（`D-14`）。
   - 决策记录须承载最强反论、放弃的能力与可观察验收面（`D-22`）。
   - 面向使用者的说明须承载消费方约定（`D-23`）。
   - 操作手册须含前置条件、真实入口路径与可观察验证（`D-24`）。
11. **删改核对**：删改前枚举该段承载的每条断言，删后逐项核对五类必保事实无丢失（`D-09`）；不得以篇幅的减少为删改依据（`D-11`）。

## 自检

落笔完成后，按规范册逐条核对：每条自身的判定口径与语义判据即该条的核对方式，不在此处另立清单。
