# 运行 DSH 的机器：SSH 管理

本 skill 约束对运行 DSH 的目标机器进行操作系统级检查与管理。agent 的 Bash shell 可能位于容器、虚拟机或其他执行环境中，不得把它默认当作宿主机，也不得用它替代到目标机器的 SSH 连接。

## 范围与护栏

- 只管理用户明确指定的运行 DSH 的机器；物理 hypervisor、上层宿主机、其他 guest 与容器都是不同目标，除非用户明确选定，不得连带操作。
- 读取、修改系统配置、用户级 D-Bus/Secret Service、keyring、系统服务、包与网络设置时，必须通过已配置的 SSH 设备目标执行；工作区文件改动仍在当前仓库按对应 skill 操作。
- SSH 只是传输通道，不代表目标身份已验证、用户图形会话已接入或 keyring 已解锁。
- 不索取或输出 SSH 密码、私钥、keyring 密码、token；不把秘密放入命令行参数、环境回显、日志或仓库文件。
- 不使用 `sshpass`、`StrictHostKeyChecking=no`、未经核验的新主机指纹或猜测的 IP/用户名；需要调整 SSH 信任或认证时先停止并取得用户或管理员提供的安全配置。
- 不执行超出明确授权范围的 `sudo`、服务重启、凭证库替换、文件删除、权限递归修改或其他破坏性操作。

## 连接前确认

1. 读取用户给出的 SSH 设备别名或昵称；先按 `ssh-device-linking` skill 的流程使用 `device_target` 解析已配置目标，不猜别名、地址、账号或密钥。
2. `device_target` 只解析目标，不探测网络也不建立 SSH 连接；解析成功后，用返回的主机/IP、端口、用户名准备连接，不把昵称当作连接地址。若当前工具版本同时返回 SSH key 文件路径或命令，可采用该路径；否则从已配置 SSH target 的密钥路径或用户已给出的路径取得；仍缺失时向用户确认。
3. `device_target` 返回未找到或歧义时，停止远程操作并请用户给出已配置目标或完成设备配置；不得回退为在当前 Bash shell 上改动系统状态。
4. 连接前用只读命令确认目标主机名、有效用户、操作系统以及可用时的虚拟化类型，并与用户指定的目标比较；任何一项不符或无法区分 guest 与 hypervisor 时先暂停确认。
5. 连接和核验始终保留 SSH 主机密钥校验；不在命令输出中打印完整环境变量，因为其中可能包含秘密。

## 推荐连接方式

对已解析且可直接到达的目标，优先使用明确的主机/IP、端口、用户名与私钥文件路径直连，不使用昵称或 SSH alias 作为本次连接地址：

```bash
ssh -F /dev/null -i "$SSH_KEY" -p "$SSH_PORT" "${SSH_USER}@${SSH_HOST}" '<只读命令>'
```

`SSH_KEY` 必须是私钥文件路径，不是私钥内容；优先取 `device_target` 返回的路径。若该信息未提供，向用户确认密钥文件路径，不索取或读取私钥内容。该命令显式绑定 endpoint 和认证文件，`-F /dev/null` 避免系统或用户 SSH 配置中的权限错误拦截直连；主机密钥校验仍保持 OpenSSH 默认行为，禁止添加 `StrictHostKeyChecking=no`。

此方式只适用于目标可直接到达且不依赖 `ProxyJump`、`HostKeyAlias`、特殊 known-hosts 文件或其他 ssh_config 设置的情况；需要这些设置时，不能用 `/dev/null` 配置假装连接等价，应使用经核验且权限正确的 SSH 配置。若私钥对当前 sandbox 用户不可读，显式 `-i` 也不会改变进程身份或权限；停止在该 sandbox 重试，不复制密钥、不放宽权限，改由有权使用该密钥的授权环境执行。

先运行只读身份核验，再执行用户要求的只读检查。SSH 返回 `known_hosts` 只读更新警告时保留并报告警告，只有身份检查一致且无主机密钥不匹配时才继续；任何主机密钥校验失败均停止并请用户/管理员处理。输出结果注明已验证的目标身份、退出码与未验证项。

## 执行与验证

- 先通过 SSH 读取目标文件、服务状态、用户身份与相关配置，再按用户授权执行最小改动；修改前保留可恢复副本，且不得覆盖与本次需求无关的状态。
- 涉及 Secret Service 或 keyring 时，在目标机器上确认实际执行用户、`XDG_RUNTIME_DIR`、D-Bus 地址是否存在、默认 collection 与锁定状态；只检查变量是否存在，不输出其余环境变量。
- SSH 连接成功不能证明目标会话的 `login` keyring 已解锁；检查该 SSH 会话实际看到的 Secret Service 与 collection 锁定状态，不根据 D-Bus socket 存在、用户登录成功或终端无错误推断凭证库可用。
- 若该 SSH 会话没有可用的已解锁 Secret Service，不猜密码、不使用明文回退，也不删除或重置 keyring；先让用户或管理员在目标机器上配置可用凭证库。
- 每次写操作后，使用同一已核验的主机/IP、端口、用户名与 SSH key 重新读取目标状态并核对退出码；涉及 DSH 消费的配置时，还要在 DSH 实际运行环境中验证它能看到该状态。
- 无法从 SSH 会话证明目标、权限、作用域或后置条件时，停止并报告已验证面与未验证面，不把本地 shell 的结果冒充为远端结果。

## 与其他流程的边界

- Git 仓库状态、提交、同步与发布仍按[版本管理 skill](../version-management/SKILL.md)执行；本 skill 只负责目标机器的身份边界与系统级 SSH 操作。
- 连接 Home Media Pilot 等业务服务时使用对应业务 skill，不把业务 API 操作扩展成宿主机管理。
