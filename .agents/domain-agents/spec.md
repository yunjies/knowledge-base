# 通用领域 agent 脚手架规范

## 调用模型

领域 agent 是通用脚手架，不按领域知识、项目或知识条目创建持久实例。每次调用由主 agent 选定的活动领域、该领域的知识资源、授权项目仓库和通用工具共同组装。活动领域与访问范围由可信调用装配提供；模型不得通过工具参数自行扩大或切换它们。

调用按 **agent → 知识库 → 源码** 的顺序进行：agent 先取得自身行为指令，再通过登记工具读取任务所需的领域知识，最后在需要核对实现时读取授权源码。领域知识统一位于 `assets/domain-knowledge/<领域标识>/`；独立源码仓库直接位于 `assets/projects/<仓库标识>/`。领域知识与源码分离，源码是实现事实的权威源，知识目录中的索引只登记定位和解析元数据，不复制源码或权威文档正文。

## 通用领域知识类型

领域可以登记下列通用知识类型。类型描述共享的查询契约，具体内容、领域规则和必需性由领域维护者决定。

| 类型 | 承载内容 | 查询用途 |
| --- | --- | --- |
| 项目与源码定位 | 仓库标识、工程相对根路径、用途及源码读取范围 | 确认源码仓库位置，再按授权路径读取实现 |
| 已实现流程 | 功能入口、主要分支、失败出口与组件交接 | 先理解业务行为，再检查实现 |
| DSH 集成部署 | 向 DSH profile 装载项目能力的前置条件、步骤与验证；构建/测试说明由项目仓库拥有时只登记索引 | 将项目能力接入 DSH，而不复制项目已有构建与测试说明 |
| 版本管理 | 分支、提交、同步、发布与远端操作约束 | 变更项目或发布前取得正确版本策略 |
| 测试规范 | 变更类别、测试层、判据资源、命令入口与未覆盖面 | 按改动风险选择足以证伪的验证 |
| 审核流程入口 | 通用 audit 流程与视角的资源引用；领域只登记通用 audit 无法提供的领域特有审查边界 | 调用通用审核流程，不在领域知识中复制审核 workflow |
| 路径与能力策略 | 当前调用可读、可写的知识资源和源码根、拒绝条件 | 在每次 I/O 前执行实际授权检查 |
| 操作方式映射 | 操作类别到有限 `methodId` 枚举及权威说明资源 ID 的映射 | 先读取选定方式，再检索对应说明或调用 handler |
| 领域业务规则 | 领域术语、数据模型、策略、工作流及业务脚手架入口 | 执行该领域特有任务 |

领域知识记录采用带 schema 版本的结构化数据。资源记录只保存稳定 ID、类型、权威位置、读取上限和必要解析元数据；正文由登记的权威源按需提供。源码仓库位置以活动调用收到的工作区内路径为准，远端、分支和提交状态等可由仓库自身取回的事实不得在知识记录中另造副本。

对版本管理等存在多种可执行方式的操作，工具先从活动调用绑定的项目策略中读取已登记的 `methodId` 枚举，再按该枚举检索唯一映射的权威说明资源或调用对应 handler。版本控制场景先调用方式解析工具，取得诸如 `github-cli` 的方法标识；随后只把该标识交给说明检索工具，由工具返回登记资源的链接或有界正文。模型不得根据任务措辞、项目名字面或上下文语义自行挑选方法、拼接链接或改走其它执行方式。

方式目录必须将每个方法标识映射到唯一资源 ID 或 handler ID。未知方法、映射缺失或资源未登记时返回结构化错误并停止；禁止回退到默认方法、猜测 URL 或从自由文本推断。

## 通用脚手架与领域业务脚手架

通用脚手架包含运行指令、Host tool 声明、确定性 handler、通用 schema、活动调用范围校验和安全反例测试。通用代码定义知识与源码的读取协议，不包含具体领域业务事实。

领域维护者可在 `assets/domain-knowledge/<领域标识>/` 下维护领域业务数据、领域专属脚手架、lint 和 tests。领域业务脚手架只在调用任务需要时由主 agent 装配；它不构成一个常驻的领域 agent 实例，也不得复制通用工具的权限检查实现来代替通用脚手架。

所有领域知识变更统一走 `domain-knowledge` → `domain-tests` → `domain-knowledge-validation`（`pytest`）流程。领域 worker 从结构化测试规范与操作映射读取本领域测试资源，再调用固定的 `run_domain_knowledge_lint` runner 执行 `uv`/`pytest`，向 coordinator 返回实际命令、stdout/stderr、退出码、截断状态、覆盖面和未覆盖面。runner 不接受模型提供的命令或路径，通过 Host subprocess service 在已绑定工作区运行，并受工具超时与调用取消信号管理。领域间只允许测试内容不同，不允许自行改变测试发现顺序、证据要求或 PASS 判据；没有实际执行结果时，worker 必须报告未验证。manifest 校验器拒绝缺少该契约的领域。

## 1. 单领域调用与工具约束

### DA-01 单领域调用边界
- **模态**: must
- **scope**: 每次领域 subagent 调用及其装配的知识资源
- **动作**: 为每次调用声明活动领域，并在装配时登记其纳入和排除范围
- **产出物**: 可判定的调用范围
  - **形态**: 一个非空活动领域标识、领域知识资源集合、授权项目仓库集合及其纳入/排除边界
  - **判定口径**: 每项被读取的领域事实都能唯一归入活动领域；存在两个合理领域归属时不得装配
  - **语义判据**: 调用中的工具能否仅凭模型改变的参数访问另一领域；能则调用范围不成立

### DA-02 工具是知识与源码入口
- **模态**: must
- **scope**: 领域 agent 获取知识事实、源码事实或执行领域操作
- **动作**: 只调用本次调用作用域内已注册且已授权的 host tools
- **产出物**: 可追溯的工具操作
  - **形态**: 工具名、结构化参数、返回值及资源/仓库标识
  - **判定口径**: 每项由工具取得的知识或源码事实均关联到已登记资源或授权仓库；agent 指令不得授权直接遍历、搜索或读取知识存储与源码目录
  - **语义判据**: 没有工具返回时，agent 是否仍能直接取得或断言受保护事实；能则访问边界失效

### DA-03 可重复行为由脚本承载
- **模态**: must
- **scope**: 资源读取、源码读取、路径授权、策略查询、知识变更与 workflow 转移
- **动作**: 将可重复的操作逻辑实现为具名脚本 handler，并由 host tool 定义调用
- **产出物**: 可调用的脚本接口
  - **形态**: 每个工具有具名 handler、输入 schema、输出 schema、权限检查及失败结果
  - **判定口径**: 每个模型可调用工具均由脚本 handler 实现；agent prompt 不承担路径解析、规则复制或状态转移逻辑
  - **语义判据**: 相同结构化输入是否由确定性代码给出同类结果；依赖提示词临场重建规则的操作不符合本条

### DA-04 行为数据结构化
- **模态**: must
- **scope**: 领域资源索引、源码仓库登记、操作方式映射、路径策略、测试规范、审核 workflow 与领域业务数据
- **动作**: 以具 schema 版本的 JSON 数据承载可枚举、可判定的领域信息
- **产出物**: 可验证的结构化数据
  - **形态**: JSON 文档含 `schemaVersion`、`domainId` 及按 schema 定义的记录
  - **判定口径**: 数据可被 JSON parser 解析且通过对应 schema；工具实现不从自由文本推断权限、资源位置或 workflow 转移
  - **语义判据**: 若值可表示为有限枚举、记录、路径规则或状态转移，它是否仍被埋在 prompt 自由文本中；是则结构化不充分

### DA-05 权威知识按需读取
- **模态**: must
- **scope**: 以已有文档、配置或源码为权威源的领域事实
- **动作**: 使用结构化资源索引将资源 ID 映射到单一权威源，并按任务调用检索工具
- **产出物**: 与权威源一致的读取结果
  - **形态**: 资源 ID、权威源路径、请求范围、返回内容与源版本
  - **判定口径**: 资源索引只保存定位和解析元数据，不复制权威源正文；读取工具只接受登记的资源或仓库标识及有界查询参数
  - **语义判据**: 权威源更新后，工具结果能否在不改写第二份正文的情况下反映更新；不能则索引存放了事实副本

### DA-06 读取与写入范围由脚本强制
- **模态**: must
- **scope**: 领域 agent 发起的知识读取、源码读取与写入
- **动作**: 从可信调用上下文和结构化 path policy 取得活动领域及允许范围，并在每次 I/O 前执行归属检查
- **产出物**: 被策略约束的路径操作
  - **形态**: 每项路径规则含操作类型、允许资源/仓库、允许路径或路径模式、拒绝条件及权威策略标识
  - **判定口径**: 未登记资源、越域路径、路径穿越和符号链接越界均在 I/O 前被拒绝；模型提供的原始路径不得直接交给文件系统
  - **语义判据**: 绕过 agent 指令或篡改工具参数后，handler 是否仍无法访问本次调用授权范围外的路径；能则策略仅为提示而非执行边界

### DA-07 测试规范可结构化检索
- **模态**: must
- **scope**: 领域 agent 需要为变更选择验证方式
- **动作**: 以结构化变更类别映射测试层、判据资源与执行入口，并按请求返回所需规范
- **产出物**: 可追溯的测试计划
  - **形态**: 变更类别、测试层、判据资源 ID、验证入口与未覆盖边界
  - **判定口径**: 每个登记的变更类别均解析到至少一项测试判据；未登记类别明确返回未知而不默认跳过测试
  - **语义判据**: 返回的验证是否能证伪该变更的主要失败模式；只返回命令而没有相应判据不构成测试规范

### DA-08 审核复用通用 audit workflow
- **模态**: must
- **scope**: 领域 agent 执行需分阶段、需主 agent 编排的审核流程
- **动作**: 按通用 audit workflow 数据验证当前阶段输入并返回下一阶段契约；领域知识不得复制通用审核流程，领域特有审核视角只作为补充资源登记；worker 以 `submit_audit_findings` 提交结构化发现或显式空清单，工具验证每条发现的源码路径范围与行证据
- **产出物**: 可复算的审核执行状态
  - **形态**: 通用 workflow ID、阶段序列、阶段输入输出、完成状态、subagent 结果引用（含结构化领域发现及其源版本证据）与最终判定
  - **判定口径**: 每次转移均符合通用 audit workflow 中登记的边；缺失必需产物、越序推进或失败状态均被拒绝
  - **语义判据**: 主 agent 是否持有跨领域和整体 verdict 的责任，领域 subagent 是否只提交本领域证据而不自授最终通过

### DA-09 领域 worker 无知识/源码写权限
- **模态**: must
- **scope**: 一次性领域 worker 可用的知识与源码工具，以及领域知识 lint runner
- **动作**: 注册读取、目录发现、测试/方法策略查询工具和一个不接受任意命令或路径的固定领域知识 lint runner；把知识或源码变更建议交回 coordinator
- **产出物**: 只读事实、路径引用、lint 实测结果与可供 coordinator 处理的变更建议
  - **形态**: resourceId、仓库相对路径、版本、行范围、证据或建议；不存在 worker 知识/源码写入工具；lint runner 只执行固定 pytest argv 并返回有界输出
  - **判定口径**: child 的可见全局工具被 restrict 且所有非领域工具被 guard 拒绝；任何知识或源码写入都不能由该 child 完成；lint runner 不接收任意命令/路径，退出码与有界输出由受管理的 subprocess service 返回
  - **语义判据**: 改变用户任务措辞、resourceId 或相对路径都不能获得写能力；变更由持有协调与审核责任的主 agent 通过自己的权限处理

### DA-10 失败时封闭拒绝
- **模态**: must
- **scope**: 数据损坏、资源未登记、授权不足、路径不符、版本冲突、工具异常或 workflow 输入缺失
- **动作**: 返回结构化失败结果并停止该次操作，不回退到直接文件访问或自由文本推断
- **产出物**: 可诊断的失败响应
  - **形态**: 稳定错误码、失败阶段、安全可公开的原因及已完成副作用
  - **判定口径**: 所有失败分支均返回错误而非成功值；拒绝发生在受保护 I/O 之前，或明确列出已经完成的副作用
  - **语义判据**: 调用者能否区分未执行、部分执行与已完成；无法区分时不得继续推进 workflow

### DA-11 工具仅暴露活动调用能力
- **模态**: must
- **scope**: 领域 agent 的 Host Tool Registry 组合
- **动作**: 将通用工具注册在当前 agent 调用作用域，并让工具执行期校验活动领域、数据根与仓库范围
- **产出物**: 隔离的工具可见面
  - **形态**: 通用 preset 的工具声明、可信调用范围及工具执行期范围校验
  - **判定口径**: 无关 agent 看不到领域工具；修改工具参数中的领域或仓库标识不能扩大本次调用的资源索引、path policy 或源码根
  - **语义判据**: 工具包被其他 preset 复用或多个调用并行时，是否仍有执行期隔离；仅依赖工具说明或隐藏 schema 不算隔离

### DA-12 通用脚手架与领域业务分别验收
- **模态**: must
- **scope**: 通用脚手架加载及领域知识/业务脚手架发布
- **动作**: 通用脚手架通过共享 lint/tests，领域业务通过其领域目录内的 lint/tests；分别映射各自适用的规范和行为证据
- **产出物**: 可复算的分层验收结果
  - **形态**: 通用规则、测试或宿主证据位置、运行结果及未验证边界；领域侧另有其业务测试结果
  - **判定口径**: 通用测试覆盖 DA-01 至 DA-13 的共用契约与反例；领域测试覆盖该领域数据 schema、资源引用、业务脚手架和领域特有失败模式，并由 worker 通过统一的 `domain-knowledge` → `domain-tests` → `domain-knowledge-validation`（`pytest`）契约发现及固定 runner 执行；任一适用测试失败均阻止相应层级加载，未执行不得判为通过
  - **语义判据**: 测试能否在对应约束被移除时转红；只检查文件存在、工具名称或提示词字面提及不构成行为验收

### DA-13 操作方式由结构化枚举确定
- **模态**: must
- **scope**: 版本管理、部署、测试等存在多种执行方法的工具操作
- **动作**: 先由 `get_operation_method` 按活动项目的结构化策略解析 `operationId` 并返回已登记的 `methodId` 枚举及唯一 `resourceId`；再将该 `resourceId` 交给 `get_knowledge_resource`，或将 `methodId` 交给对应 handler
- **产出物**: 无语义推断的标准化方法选择
  - **形态**: `operationId` 取工具声明的封闭枚举；`methodId` 取活动项目策略登记的枚举；每个 `methodId` 唯一映射到资源 ID 或 handler ID，方法解析结果由下一次工具调用原样消费
  - **判定口径**: 每个方法标识都在活动项目策略中登记且唯一映射到资源或 handler；未知、缺失、重复映射或资源不可读时返回结构化失败并停止，不回退到默认方法
  - **语义判据**: 保持活动调用策略不变，只改用户任务的自然语言描述，工具解析出的 `methodId` 是否保持不变；若会变化，或需要模型从措辞推断 GitHub CLI 等方式，则标准化失败
